# 📖 Справочник и архитектура текстов `just1kbot`

Этот документ описывает модульную структуру текстовых файлов бота, принципы Single Source of Truth (SSOT), правила разметки Telegram и руководство по редактированию.

---

## 🏛 Архитектурные принципы каталога текстов

1. **Строгий SSOT (Один ключ = Один канонический файл):**
   - Каждый текстовый ключ определяется ровно в **одном** файле своей предметной области.
   - Отсутствуют неявные переопределения (`overrides.py` полностью упразднен).
   - Если один и тот же ключ случайно появляется в двух файлах, реестр `bot.texts` немедленно завершает инициализацию ошибкой `SSOT Violation: Duplicate text key`.

2. **Модульная организация по предметным областям (`bot/texts_data/`):**

```text
bot/texts_data/
├── user/                  # Пользовательский интерфейс и экраны
│   ├── hub.py             # Главное меню, профиль пользователя, балансы
│   ├── devices.py         # Создание, список, управление и удаление устройств
│   ├── connection.py      # Настройки подключения, MTProto, INCY
│   ├── payments.py        # Пополнение баланса, покупка тарифов, чеки, ЮKassa
│   ├── subscription.py    # Витрина подписок и калькулятор смены тарифа
│   ├── referral.py        # Реферальная программа, ссылки, статистика
│   └── support.py         # FAQ, база знаний, контакты поддержки, TOS/Privacy
│
├── admin/                 # Панель администратора
│   ├── dashboard.py       # Главный экран админки, режим техработ, статистика
│   ├── servers.py         # Список, добавление, редактирование, ping и удаление серверов
│   ├── users.py           # Поиск пользователей, карточка, блокировки, ручной баланс
│   ├── subscriptions.py   # Выдача, продление, сокращение и смена подписок
│   ├── tariffs.py         # Управление тарифами, ценами и лимитами
│   ├── payments.py        # Логи покупок, платежные карточки, возвраты
│   ├── disputes.py        # Управление банковскими спорами (chargebacks)
│   ├── queues.py          # Диагностика очередей платежей и задач
│   └── broadcast.py       # Массовые рассылки и таргетинг
│
├── common/                # Общие переиспользуемые элементы
│   ├── buttons.py         # Стандартные кнопки навигации (Назад, Отмена, Меню)
│   ├── errors.py          # Системные ошибки, отказы доступа, fallback
│   └── status.py          # Бейджи статусов, разделители, форматирование
│
└── runtime/               # Системные уведомления и воркеры
    ├── alerts.py          # Критические алерты бота и мониторинга
    └── workers.py         # Напоминания об истечении подписки (3d/1d/2h), бонусы, очереди
```

Все тексты агрегируются в **[`bot/texts.py`](../texts.py)** и доступны в кодовой базе как `texts.KEY_NAME`.

## ⚙️ Правила редактирования и HTML-разметки

1. **Разрешенные HTML-теги Telegram:**
   - Жирный текст: `<b>Текст</b>`
   - Курсив: `<i>Текст</i>`
   - Моноширинный текст (для копирования): `<code>Текст</code>`
   - Многострочный блок кода: `<pre>Текст</pre>`
   - Спойлер: `<tg-spoiler>Текст</tg-spoiler>`
   - Раскрывающийся блок цитаты: `<blockquote expandable>Текст</blockquote>`
   - Ссылки: `<a href="https://...">Текст</a>`

2. **Правила использования плейсхолдеров `{var_name}`:**
   - Если в тексте указан плейсхолдер в фигурных скобках (например, `{name}`, `{valid_until}`, `{amount}`), он подставляется программно через `.format(...)`.
   - **Не удаляйте и не переименовывайте плейсхолдеры**, если вызывающий код передает их.
   - Символ фигурной скобки экранируется удвоением: `{{` или `}}`.

3. **Бизнес-правила наименований (требование эквайринга/платежных систем):**
   - В текстах для пользователей **запрещено** использовать слова «VPN», «ВПН», «обход блокировок», «прокси».
   - Используйте формулировки: *«Подключение»*, *«Доступ к сервису»*, *«Устройства»*, *«Тариф»*.
   - Исключение: технические названия протокола и клиентов (`AmneziaVPN`, `AmneziaWG`, `DefaultVPN`, `.conf`, `.vpn`, `vpn://`).

## 🔍 Индекс основных плейсхолдеров по разделам

### 1. Главное меню (`HUB_HEADER`)
- `{name}` — Имя пользователя в Telegram.
- `{telegram_id}` — Telegram ID пользователя.
- `{status}` — Статус подписки (🟢 Активна / 🔴 Истекла).
- `{valid_until}` — Дата окончания подписки (например, `15.09.2026 18:30 UTC`).
- `{days_left}` — Человекочитаемый остаток (например, `14 дн.`).
- `{devices_count}` — Число активных устройств.
- `{device_limit}` — Максимальный лимит устройств по тарифу.
- `{real_balance}` — Основной баланс в рублях.
- `{bonus_balance}` — Бонусный баланс в рублях.
- `{inviter_line}` — Информация о пригласившем пользователе.

### 2. Карточка устройства (`DEVICE_MANAGE_HEADER`, `DEVICE_SHOW_KEY`)
- `{device_name}` — Название устройства.
- `{country_display}` — Флаг и название страны локации.
- `{protocol}` — Протокол (`AmneziaWG`).
- `{traffic_total}` — Общий объем переданного трафика.
- `{last_connected}` — Время последней активности.
- `{raw_config}` — Ключ подключения `vpn://...`.

### 3. Админка: Серверы (`ADMIN_SERVER_ADDED`, `ADMIN_SERVER_DELETE_CONFIRM`)
- `{flag}` — Эмодзи флага страны.
- `{name}` — Название сервера.
- `{protocol}` — Протокол сервера.
- `{max_clients}` — Максимальный лимит клиентов.
- `{api_url}` — API URL сервера.
- `{profiles_count}` — Количество привязанных устройств.

### 4. Админка: Подписки (`ADMIN_SUB_CONFIRM_EXTEND`, `ADMIN_SUB_CONFIRM_GRANT`, `ADMIN_SUB_TARIFF_CHANGED`)
- `{telegram_id}` — Telegram ID пользователя.
- `{tariff_name}` — Название тарифа.
- `{days_text}` — Выбранный срок продления.
- `{new_end}` — Новая дата окончания доступа.
- `{current_end}` — Текущая дата окончания доступа.
- `{devices_count}` — Число созданных устройств.
- `{device_limit}` — Лимит устройств по тарифу.

## ⚡️ Горячая перезагрузка текстов в Dev-режиме

Для обновления текстов без перезапуска процесса бота:
```python
from bot.texts import reload_texts
reload_texts()
```
При вызове функции все доменные модули перезагружаются в память с валидацией ключей.
