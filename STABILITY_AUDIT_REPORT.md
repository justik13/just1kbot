# 🛡️ STABILITY AUDIT REPORT: just1kbot (Feature Freeze)

## 🔴 BLOCKER / CRITICAL (Критичные баги — запрещено в Prod)

### 1. Слепой перехват исключений (Blind Exception Catching & Silent Failures)
- **Проблема:** Во многих местах, особенно в админ-хендлерах (`broadcast.py`) и парсере VPN, используется широкая конструкция `except Exception:` (иногда даже без логирования или без `re-raise`), которая "проглатывает" ошибки. Если отвалится база или сеть, система молча продолжит работу, оставляя процесс в неконсистентном состоянии, скрывая реальные проблемы (например, падение бэкграунд-тасок). Ruff выдает нарушение `BLE001`.
- **Локация:** 
  - `bot/handlers/admin/broadcast.py` (строки 171, 368, 373, 445 и далее)
  - `utils/vpn_parser.py` (строки 183-184, 283-284)
- **Риск:** Скрытые падения (silent failures), невозможность понять причины остановки бродкастов, потеря данных, невозможность починить парсер при изменениях API. В проде такие ошибки не попадут в `global_error_handler` и алерты админам не придут.
- **Решение:**
```diff
-    except Exception as e:
-        logger.error(f"build_conf_file_from_dict: unexpected error: {e}", exc_info=True)
-        return None
+    except Exception:
+        logger.exception("build_conf_file_from_dict: unexpected error")
+        # Либо прокинуть raise, если это критичная бизнес-логика
```

### 2. Уязвимый и хрупкий парсер конфигураций
- **Проблема:** Вложенные `if/else` и жесткая привязка к строкам (`[Interface]`) при модификации MTU и DNS в конфигах Wireguard, что ведет к ошибкам генерации (violation of SIM102/SIM103). При сбое парсера возвращается `None` и конфигурация не выдается пользователю. 
- **Локация:** `utils/vpn_parser.py` (строки 219, 276).
- **Риск:** Пользователи не смогут получить конфигурационный файл, если API Amnezia незначительно изменит формат вывода.
- **Решение:** Провести полный рефакторинг с использованием регулярок или INI-парсера, убрать вложенность и добавить жесткую типизацию на вход.

## 🟡 MAJOR (Серьезные баги, техдолг и потенциальные падения)

### 1. Hardcoded Bind All Interfaces (0.0.0.0)
- **Проблема:** Webhook сервер (`aiohttp.web.TCPSite`) жестко биндится на `0.0.0.0`. 
- **Локация:** `bot/main.py:275`, `utils/security.py:19`.
- **Риск:** Предупреждение Bandit `B104`. Если контейнер бота запускается с `--network host` или порты пробрасываются напрямую без локального reverse proxy, порт становится публично доступен всему интернету в обход ожидаемой безопасности, что может привести к DDoS-атакам на endpoint вебхуков.
- **Решение:**
```diff
-    site = web.TCPSite(runner, "0.0.0.0", port)
+    host = os.getenv("WEBHOOK_HOST", "0.0.0.0" if is_docker else "127.0.0.1")
+    site = web.TCPSite(runner, host, port)
```

### 2. Массовый технический долг в Type Hints (Python 3.11+)
- **Проблема:** Код использует устаревший синтаксис `Optional[Type]` вместо современного `Type | None`. Линтер Ruff выявил 350+ таких нарушений (правило `UP045`).
- **Локация:** Весь проект (в основном `utils/vpn_parser.py`, `services/*`).
- **Риск:** Засорение кодовой базы, снижение читаемости, несоответствие стандартам проекта на Python 3.11+.
- **Решение:** Прогнать автоматический фикс через `ruff check --fix .`.

## 🟢 MINOR (Код-стайл, мертвый код, мелкая оптимизация)

### 1. Проблема N+1 запросов при загрузке пользователей в Админ-панели
- **Проблема:** В репозитории загружаются пользователи с их профилями `selectinload(User.profiles)`, но не загружается их текущий тариф `User.current_tariff`. 
- **Локация:** `database/repositories/users_repo.py:164` (`get_users_paginated_with_profiles`).
- **Решение:** Добавить `.options(selectinload(User.current_tariff))` если этот связанный объект используется при рендеринге списков в админке.

### 2. Неправильное использование логгера
- **Проблема:** В проекте используется `logger.error(..., exc_info=True)` (нарушение `G201`).
- **Локация:** Встречается в `utils/vpn_parser.py` и некоторых хендлерах.
- **Решение:** Заменить на стандартный `logger.exception(...)`.
