# Just1kBot

Центральный серверный контроллер и Telegram-бот для управления закрытым сервисом защищенного доступа в интернет.

Архитектура комплекса разделена на два компонента:
- **`just1kbot`** (текущий репозиторий) — Telegram-бот, веб-интерфейс инструкций и поддержки, биллинг, база данных, выдача подписок и мониторинг узлов.
- **[`just1knode`](https://github.com/justik13/just1knode)** — автономный агент серверных узлов, управляющий службами Xray, Nginx и системным периметром.

---

## Направления доступа и протоколы

Сервис предоставляет два независимых направления подключения:

1. **Стандартный доступ (строго VLESS TLS):**
   - Прямое подключение к выделенным узлам на собственном домене.
   - Выдача конфигураций через HTTP Subscription Feed (`/sub/access/{token}`) для клиентов `INCY` и `Happ` (iOS, Android, Windows, macOS, Linux).
   - Обязательная аппаратная привязка и квотирование устройств по HWID.
   - Защита от блокировок ТСПУ: TLS-фингерпринт `firefox` по умолчанию, фрагментация TCP ClientHello (`split` на уровне TLS) и раздельная маршрутизация (прямой доступ к российским ресурсам без туннелирования).
   - *Примечание по AmneziaWG (AWG):* протокол полностью выведен из эксплуатации в продакшене с 27.10.2026 из-за массовых блокировок IP со стороны ТСПУ РКН. Выдача ключей и файлов `.conf`/`.vpn` прекращена.

2. **Белый Интернет (для условий жестких блокировок мобильных сетей и белых списков):**
   - Протокол: Xray VLESS over XHTTP с каскадной топологией Origin (РФ) ➔ Relay (Европа) через CDN Yandex Cloud.
   - Nginx Zero Buffering и Bodiless GET Uplink на Origin исключают ошибки 413 и задержки буферизации CDN.
   - Выдача строго по URL подписки (`/sub/wl/{token}`) для клиентов `INCY` и `Happ` с привязкой к HWID.
   - Ознакомительный доступ: 3 дня и 5 ГБ трафика (активируется один раз; продление, сброс и ручная выдача доступны в `/admin`).
   - Автоматический мониторинг: бот проверяет связность Origin ➔ Relay через регулярные зонды с защитой от ложных срабатываний (гистерезис 5 ошибок).

## Архитектура системы

```text
                            [ Пользователи / Клиенты ]
                                        │
            ┌───────────────────────────┴───────────────────────────┐
            ▼                                                       ▼
     [ Telegram Bot ]                                      [ INCY / Happ Client ]
  (Управление, биллинг,                                   (iOS, Android, Windows,
   поддержка, рассылки)                                        macOS, Linux)
            │                                                       │
            ▼                                         ┌─────────────┴─────────────┐
  ┌───────────────────────┐                           ▼                           ▼
  │    JUST1KBOT SERVER   │                  [ Standard VLESS ]          [ White Internet ]
  │ ───────────────────── │                  (Direct VLESS TLS)         (VLESS over XHTTP)
  │ • Bot (aiogram 3)     │                           │                           │
  │ • Web Hub & Landing   │                           │                           ▼
  │   (/instructions,     │                           │                 [ Yandex Cloud CDN ]
  │    /emergency)        │                           │                           │
  │ • Caddy (HTTPS, /sub) │                           │                           ▼
  │ • PostgreSQL 16       │                           │                  [ Origin Node (РФ) ]
  │ • Redis 7.4           │                           │                 (Nginx Zero Buffering,
  │ • Task Workers        │                           │                  Bodiless GET Uplink)
  └──────────┬────────────┘                           │                           │
             │                                        │                           ▼
             │ (Управляющие API                       │                    [ Relay Nodes ]
             │  строго по BOT_IP)                     │                  (VLESS TLS за рубеж)
             ├────────────────────────────────────────┼─────────────┬─────────────┘
             ▼                                        ▼             ▼
     [ Прямые VLESS ]                          [ Origin Nodes ] [ Relay Nodes ]
     (xray-api:8444)                           (xray-api:8444)  (xray-api:8444)
            │                                                       │
            └─────────────────────────┬─────────────────────────────┘
                                      ▼
                                 [ Интернет ]
```

### Сетевое взаимодействие бота с узлами
- Все узлы Xray (Origin, Relay, Direct VLESS TLS) управляются через микросервис `xray-api` (HTTPS, порт `8444`).
- Фаервол UFW на узлах открывает порт `8444` строго для IP-адреса сервера бота (`BOT_IP`). Прямые запросы извне блокируются.

## Технологический стек

| Компонент | Технологии и версии | Назначение |
|---|---|---|
| Ядро бота | Python 3.12, aiogram 3.31+, aiohttp 3.14+ | Логика Telegram-интерфейса, обработка команд и меню |
| Веб-хаб | Jinja2, HTML5, Vanilla JS | Интерактивные инструкции (`/instructions`) и аварийная форма (`/emergency`) |
| База данных | PostgreSQL 16.14-alpine, SQLAlchemy 2.0.54 (asyncpg 0.31+) | Хранение пользователей, заказов, серверов и очередей задач |
| Кэш и FSM | Redis 7.4-alpine | Хранение состояний FSM и оперативный кэш |
| Веб-сервер | Caddy 2.11.4-alpine | Reverse proxy, Auto-HTTPS, Rate Limiting, эндпоинты `/sub/*` и статика |
| Миграции БД | Alembic 1.20.0 | Управление схемой базы данных с поддержкой upgrade и downgrade |
| Биллинг | ЮKassa API | Прием платежей (СБП, банковские карты), проверка IP-диапазонов вебхуков |
| Бэкапы | `pg_dump` + `gzip` + `age` + rclone | Зашифрованные дампы с выгрузкой в Google Drive или S3/HTTPS |

## Быстрый старт: Сервер бота

### 1. Системные требования
- ОС: Ubuntu 22.04 / 24.04 или Debian 11 / 12;
- Ресурсы: минимум 1 CPU, 2 GB RAM, 10 GB диска;
- Сеть: открытые внешние порты 80 и 443 (TCP);
- Доменное имя с DNS A-записью, направленной на IP сервера.

### 2. Автоматическая установка

```bash
git clone https://github.com/justik13/just1kbot.git
cd just1kbot
sudo bash ./scripts/setup.sh
```

Мастер установки `setup.sh`:
1. Устанавливает системные пакеты (`docker`, `docker compose`, `age`, `openssl`);
2. Настраивает параметры ядра: `vm.overcommit_memory=1` (в `/etc/sysctl.d/99-just1kbot.conf` для Redis) и Stealth ICMP (`net.ipv4.icmp_echo_ignore_all=1`);
3. Запрашивает токен бота, ID администратора, домен и API-ключи ЮKassa с валидацией формата;
4. Генерирует ключи шифрования (`DB_ENCRYPTION_KEY`, пароли PostgreSQL/Redis, ключевую пару `age`);
5. Настраивает автоматический бэкап в cron и регистрирует системную утилиту `/usr/local/bin/just1kbot`.

## Управление через CLI (`just1kbot`)

Основное администрирование на сервере бота выполняется через утилиту `just1kbot`.

### Интерактивное меню

```bash
just1kbot
```

### Прямые команды CLI

| Команда | Описание |
|---|---|
| `just1kbot status` | Статус контейнеров Docker, потребление памяти, дата последнего бэкапа |
| `just1kbot logs [сервис]` | Просмотр логов: `bot`, `caddy`, `db`, `redis` или `all` (по умолчанию: `bot`) |
| `just1kbot update` | Безопасное обновление: бэкап БД -> git pull -> сборка -> миграции Alembic |
| `just1kbot doctor` | Диагностика: сеть, DNS, SSL-сертификаты, Telegram API, вебхуки, аудит портов UFW |
| `just1kbot preflight` | Проверка корректности переменных окружения в `.env` |
| `just1kbot backup` | Создание зашифрованного дампа базы данных |
| `just1kbot gdrive` | Интерактивная настройка автоматической выгрузки бэкапов в Google Drive |
| `just1kbot restore [файл]` | Восстановление базы данных из локального бэкапа |
| `just1kbot config` | Редактирование `.env` с последующим пересозданием сервисов |
| `just1kbot restart [сервис]` | Перезапуск отдельного контейнера или всего проекта |
| `just1kbot start` | Запуск всех сервисов проекта |
| `just1kbot stop` | Остановка всех сервисов проекта |
| `just1kbot version` | Отображение версии проекта и текущего git-коммита |
| `just1kbot uninstall` | Полное удаление проекта (флаги: `--force`, `--purge-backups`, `--keep-backups`) |

## Резервное копирование и восстановление

### Схема шифрования дампа

```text
PostgreSQL ──> pg_dump ──> gzip ──> age (BACKUP_AGE_RECIPIENT) ──> ./backups/*.sql.gz.age
```

Публичный ключ `BACKUP_AGE_RECIPIENT` хранится на сервере в `.env`. Закрытый ключ генерируется при установке, сохраняется администратором локально и на сервере не хранится.

### Автоматическая выгрузка в Google Drive

```bash
just1kbot gdrive
```

Команда запускает авторизацию по OAuth 2.0 и связывает контейнер `backup` с Google Drive через `rclone`. Бэкапы выгружаются сразу после создания по расписанию cron. Подробное руководство: [docs/GOOGLE_DRIVE_BACKUP.md](docs/GOOGLE_DRIVE_BACKUP.md).

### Выгрузка на S3 / HTTPS

Для отправки на совместимое S3/HTTPS-хранилище укажите в `.env`:

```ini
BACKUP_REMOTE_URI='https://storage.example.com/backups/{filename}'
BACKUP_REMOTE_TOKEN='your_secret_token'
```

### Восстановление базы данных

```bash
just1kbot restore
```

Скрипт выводит список доступных зашифрованных дампов, принимает закрытый ключ `age` от администратора, расшифровывает дамп во временный файл и восстанавливает данные в PostgreSQL.

## Регламент обновления в Production

Обновление распределенного сервиса выполняется в следующем порядке:

1. **Слияние Pull Request на GitHub:** PR мерджит владелец репозитория после успешного прохождения проверок CI.
2. **Обновление сервера бота (`just1kbot`):**
   ```bash
   just1kbot update
   ```
   Скрипт создает аварийный дамп БД, обновляет код, собирает контейнеры, накатывает миграции Alembic и проверяет статус служб.
3. **Обновление серверных узлов (`just1knode`):**
   На каждом узле (Origin, Relay, Direct VLESS TLS) выполните:
   ```bash
   just1knode update
   just1knode doctor
   ```

## Биллинг, заказы и возвраты

1. **Пополнение баланса:**
   - Обработка платежей через шлюз ЮKassa (СБП, банковские карты).
   - Входящие вебхуки принимаются на `/yookassa/webhook` с верификацией по официальным диапазонам IP ЮKassa и защитой от повторной обработки (идемпотентность).
2. **Атомарные списания:**
   - Баланс пользователя хранится в `users.balance_kopecks`.
   - Проверка емкости серверов и валидация ограничений тарифа выполняются до списания средств.
   - При смене тарифа выполняется перерасчет неиспользованных дней.
3. **Регламент возвратов:**
   - Возврат средств выполняется владельцем вручную через личный кабинет ЮKassa.
   - Бот принимает вебхук `refund.succeeded`, фиксирует возврат в журнале операций и отзывает доступ.

## Диагностика и частые ситуации

### Запуск диагностики

```bash
just1kbot doctor
```

Проверяет: параметры ядра `sysctl`, UFW-периметр, контейнеры Docker, подключения к PostgreSQL и Redis, Caddy TLS/DNS, токен Telegram Bot API и доступность ЮKassa.

### Частые инциденты

| Симптом | Причина | Решение |
|---|---|---|
| Бот не стартует или циклично перезагружается | Ошибки в `.env` или неверный `DB_ENCRYPTION_KEY` | Проверьте `just1kbot logs bot` и выполните `just1kbot preflight` |
| Ошибка 502 Bad Gateway на `/sub/wl/*` | Nginx на Origin не может связаться с ботом по TLS | Выполните `just1knode update` на Origin для сверки `proxy_ssl_name` |
| Caddy не выпускает сертификат | Закрыты порты 80/443 или не обновилась DNS A-запись | Запустите `just1kbot doctor` и проверьте доступность портов во внешнем файрволе |
| Сбои TLS-пакетов при работе через туннели | MTU интерфейса хоста меньше стандартных 1500 байт | В `docker-compose.yml` мосты зафиксированы на MTU 1440. Перезапустите контейнеры: `just1kbot restart` |
| Ошибка доступа к API узла (8444) | Сменился IP сервера бота либо порт закрыт в UFW узла | На сервере узла выполните `just1knode set-bot-ip <НОВЫЙ_IP>` |
