# Just1kBot

Telegram-бот и комплекс автоматизированного управления доступом на базе AmneziaWG 2.0 и Белого Интернета (Xray VLESS over XHTTP).

Архитектура состоит из двух компонентов: центральный контроллер бота (`just1kbot`) и агент серверных узлов (`just1knode`).

---

## Принцип управления: CLI-first

Все штатные операции обслуживания выполняются через скрипты `just1kbot` и `just1knode`.

- `just1kbot`: центральное управление на сервере бота (мониторинг статуса, резервное копирование, обновление с предпроверочным дампом БД, миграции схемы, просмотр логов, диагностика сети, интеграция с внешним Nginx, безопасное удаление).
- `just1knode`: автономное управление на каждом серверном узле (установка ролей Origin и Relay, привязка каскадов, ротация ключей Reality, обновление Xray и Nginx, 9 уровней самодиагностики `doctor`, безопасное удаление).

Прямой запуск команд вроде `docker compose build`, `docker compose up -d` или ручное редактирование конфигурационных файлов — это аварийный fallback для отладки. При штатной эксплуатации используйте CLI-утилиты.

## Возможности системы

### Для пользователей
- Два изолированных протокола:
  - AmneziaWG 2.0 (`amneziawg2`): защищенный протокол с обфускацией заголовков. Выдача конфигураций в форматах `vpn://` URI, `.vpn` для AmneziaVPN и DefaultVPN, `.conf` для клиента AmneziaWG.
  - Белый Интернет (`xray`): VLESS over XHTTP через Yandex Cloud CDN с каскадной топологией Origin -> Relay. Подписка в формате URL для клиента INCY (iOS, Android, APK) и ознакомительный триал на 3 дня (10 ГБ).
- Биллинг и баланс:
  - Пополнение баланса через ЮKassa (банковские карты, СБП);
  - Атомарное продление и смена тарифов с перерасчетом неиспользованного времени;
  - Двухфазное резервирование средств перед сетевыми операциями;
  - Реферальная программа с начислением бонусов на баланс;
  - Защита от повторной обработки транзакций и проверка подлинности вебхуков по официальным диапазонам IP.
- Управление подключениями:
  - Меню устройств в Telegram-интерфейсе;
  - Бесшовная миграция устройств между серверами AmneziaWG без изменения ключей и простоя;
  - Автоматическое обновление данных о трафике.

### Для администраторов
- Панель управления в Telegram (`/admin`):
  - Мониторинг серверов, лимитов слотов, задержки (ping) и статуса активности (активные и неактивные серверы);
  - Управление тарифами, пользователями, блокировками и диспутами;
  - Продление подписок и проверка видимости устройств Белого Интернета;
  - Таргетированные рассылки с фильтрацией по серверам и сохранением прогресса доставки;
  - Аудит административных действий и отслеживание активности (last seen);
  - Режим технических работ.
- Мониторинг узлов (`node_monitor`):
  - Фоновый healthcheck ядра Xray и Amnezia API с CAS-защитой эпох;
  - Отвязанный мониторинг выдачи подписок через CDN (`/sub/wl/ping`), исключающий ложные срабатывания по ядру Xray при сетевых задержках;
  - Персистентные алерты администраторам с гарантией доставки через очередь в PostgreSQL.

## Архитектура и надежность

Система спроектирована с учетом отказоустойчивости и строгой целостности данных:

1. Строгая изоляция контуров (Protocol Decoupling):
   Контуры AmneziaWG и Xray полностью разделены. API-клиент AmneziaWG не отправляет запросы на узлы Xray, а воркеры фильтруют серверные пулы по `Server.protocol`.
2. Проверка тарифов до списания (Pre-Debit Validation):
   Проверка ограничений тарифа и доступности серверов выполняется до списания средств с баланса.
3. Блокировки перед мутациями (Lock-Before-Mutation):
   Распределенные advisory locks в PostgreSQL захватываются до отправки сетевых запросов к внешним узлам.
4. Персистентность по умолчанию (Durable-by-Default):
   Ключи идемпотентности, очереди задач и инциденты мониторинга сохраняются в PostgreSQL и выдерживают внезапную остановку процесса.
5. Валидация перед перезапуском и защита от сбоев:
   При изменении настроек узлов через `just1knode` файлы конфигурации Nginx и Xray валидируются (`nginx -t`, `xray run -test`) до применения. Nginx перезагружается без разрыва соединений (`reload`), а Xray перезапускается с транзакционным откатом к рабочей версии при ошибке проверки.

## Быстрый старт: Сервер бота (`just1kbot`)

### 1. Автоматическая установка

Поддерживаемые ОС: Ubuntu 20.04 / 22.04 / 24.04 или Debian 11 / 12.

```bash
git clone https://github.com/justik13/just1kbot.git
cd just1kbot
sudo bash ./scripts/setup.sh
```

Интерактивный установщик `setup.sh`:
1. Проверяет и устанавливает Docker, Docker Compose, `age`, `openssl` и системные зависимости;
2. Настраивает параметр ядра `vm.overcommit_memory=1` (runtime и персистентно в `/etc/sysctl.d/99-just1kbot.conf`);
3. Запрашивает данные Telegram-бота, администратора, домен и реквизиты ЮKassa с валидацией;
4. Генерирует ключи шифрования (`DB_ENCRYPTION_KEY`, пароли PostgreSQL/Redis, пару ключей `age`);
5. Настраивает автобэкапы в `cron`, регистрирует утилиту `just1kbot` в `/usr/local/bin` и запускает контейнеры.

### 2. Консоль управления `just1kbot`

Для перехода в интерактивное меню выполните:

```bash
just1kbot
```

Вид меню:

```text

║                         🚀 JUST1KBOT CONTROL PANEL                           ║
║                     Консоль управления Telegram-ботом                        ║
╚══════════════════════════════════════════════════════════════════════════════╝

  [1] 📊 Статус системы (Healthcheck контейнеров, RAM/CPU, бэкапы)
  [2] 📜 Просмотр логов (Live stream: Bot, Caddy, Postgres, Redis)
  [3] 🔄 Безопасное обновление (Auto-backup -> Git pull -> Rebuild)
  [4] 💾 Управление бэкапами (Создать бэкап сейчас / Восстановить БД)
  [5] ⚡ Перезапуск сервисов (Restart Bot / Restart All)
  [6] 🔑 Конфигурация (Редактировать .env файл с reload)
  [7] 🩺 Диагностика (Doctor) (Проверка DNS, SSL, портов и Telegram API)
  [8] 🧹 Очистить дисковый кэш (Docker image prune)

  [10] 🗑️  Полное удаление (Uninstall Just1kBot с сервера)
```

### Прямые команды CLI `just1kbot`

Команды можно вызывать напрямую без входа в меню:

```bash
just1kbot status               # Проверить статус контейнеров, ресурсы и дату последнего бэкапа
just1kbot logs [сервис|all]    # Просмотр логов сервиса или всех контейнеров (по умолчанию: bot)
just1kbot update               # Обновление: бэкап БД, git pull, сборка, миграции и проверка
just1kbot backup               # Создать зашифрованный бэкап базы данных
just1kbot restore [файл]       # Восстановить базу данных из бэкапа
just1kbot start                # Запустить контейнеры проекта
just1kbot stop                 # Остановить контейнеры проекта
just1kbot restart [сервис]     # Перезапустить сервис или весь проект (по умолчанию: bot)
just1kbot config               # Открыть .env в редакторе с пересозданием контейнеров (--force-recreate)
just1kbot nginx-config         # Настроить конфигурацию для внешнего Nginx (Reverse Proxy)
just1kbot doctor               # Проверить сеть, DNS, SSL-сертификаты и доступ к Telegram API
just1kbot preflight            # Проверить корректность переменных в .env
just1kbot clean                # Удалить неиспользуемые Docker-образы и кэш сборщика
just1kbot uninstall            # Полное удаление проекта с подтверждением и очисткой томов
```

## Развертывание и управление узлами (`just1knode`)

Управление узлами AmneziaWG и Белого Интернета выполняется через утилиту `just1knode`.

### 1. Установка утилиты на узел

Поддерживаемые ОС: Ubuntu 22.04 / 24.04 или Debian 11 / 12.

```bash
curl -fsSL https://raw.githubusercontent.com/justik13/just1kbot/main/just1knode/just1knode.sh | bash
```

Скрипт развертывает модули в `/opt/just1knode` и создает симлинк `/usr/local/bin/just1knode`.

### 2. Настройка входного шлюза (Origin в РФ)

Origin принимает клиентский трафик через CDN Yandex Cloud, выполняет маршрутизацию и направляет зарубежный трафик на Relay-узлы:

```bash
just1knode install origin
```

Либо запустите `just1knode` без параметров и выберите пункт `[1]`.

Мастер запросит:
- Домен узла для сертификата Let's Encrypt (например, `origin.example.com`);
- Домен бота для проксирования подписок (например, `bot.example.com`);
- CDN-домен (например, `cdn.example.com`).

После настройки Nginx будет проксировать запросы `/sub/wl/*` на бота с поддержкой TLS SNI и динамического DNS-резолвера.

### 3. Настройка выходного шлюза (Relay за рубежом)

Relay принимает трафик с Origin по протоколу VLESS REALITY и выводит его в интернет:

```bash
just1knode install relay
```

Либо запустите `just1knode` без параметров и выберите пункт `[2]`.

Скрипт сгенерирует ключи REALITY, настроит службу Xray и выведет готовую команду для привязки к Origin.

### 4. Привязка Relay к Origin

На сервере Origin выполните сгенерированную команду добавления:

```bash
just1knode relay add "Германия" IP_RELAY 10443 UUID "de" "reality" PUBKEY SHORTID SNI
```

Либо выберите пункт `[1]` в меню `just1knode` на Origin (доступно добавление вставкой одной строки).
Origin настроит индивидуальный маршрут в Xray, создаст конфигурацию в Nginx и применит изменения с предварительной проверкой синтаксиса.

### Команды CLI `just1knode`

```bash
just1knode                                  # Интерактивное контекстное меню (Origin / Relay / новый)
just1knode status                           # Статус служб, портов и активных подключений
just1knode doctor                           # 9 уровней самодиагностики узла (Xray, API, TLS, Nginx, CDN)
just1knode update                           # Обновление модулей утилиты и самовосстановление конфигураций
just1knode update core                      # Обновление бинарного ядра Xray-core до актуальной версии
just1knode relay add "Название" IP ...      # Добавить Relay-узел на Origin
just1knode relay remove <код_или_id>        # Удалить Relay-узел
just1knode relay rename <код> <новое_имя>   # Переименовать Relay-узел
just1knode relay list                       # Показать список подключенных Relay-узлов
just1knode reset                            # Сбросить конфигурацию узла
just1knode uninstall                        # Полное удаление just1knode с сервера
```

Просмотр логов служб узла выполняется через системные команды:

```bash
journalctl -u xray -f        # Логи ядра Xray
journalctl -u nginx -f       # Логи веб-сервера Nginx
journalctl -u xray-api -f    # Логи внутреннего API узла
```

## Протокол обновления в Production

Порядок обновления распределенной системы:

```text
[1. GitHub Merge] ──> [2. just1kbot update] ──> [3. just1knode update]
```

### Шаг 1. Слияние PR на GitHub
Слияние Pull Request в ветку `main` выполняется владельцем репозитория на GitHub после прохождения всех проверок CI.

### Шаг 2. Обновление сервера бота (`just1kbot`)
На сервере бота выполните:

```bash
just1kbot update
```

Скрипт создаст резервную копию базы данных, получит изменения из Git, пересоберет контейнеры, применит миграции Alembic и проверит статус служб.

### Шаг 3. Обновление узлов (`just1knode`)
На серверах Origin и Relay выполните:

```bash
just1knode update
just1knode doctor
```

Утилита обновит модули, проверит конфигурации, согласует маршруты и подтвердит статус тестами самодиагностики.

## Резервное копирование и восстановление данных

Тома Docker для PostgreSQL, Redis и сертификатов Caddy сохраняются на диске хоста. Резервные копии базы данных создаются автоматически и шифруются утилитой `age` с использованием открытого ключа.

### Схема шифрования

```text
PostgreSQL ──> pg_dump ──> gzip ──> age (BACKUP_AGE_RECIPIENT) ──> ./backups/*.sql.gz.age
```

> [!CAUTION]
> Закрытый ключ `age` не должен храниться на production-сервере. На сервере находится только публичный ключ `BACKUP_AGE_RECIPIENT`. Закрытый ключ хранится на защищенном компьютере администратора и применяется только для расшифровки дампа при аварийном восстановлении.

### Удаленные бэкапы (S3 / HTTPS)

Для отправки бэкапов на удаленное хранилище укажите в `.env`:

```ini
BACKUP_REMOTE_URI='https://storage.example.com/backups/{filename}'
BACKUP_REMOTE_TOKEN='your_secret_token'
```

Архивы загружаются на удаленный эндпоинт сразу после создания.

### Восстановление базы данных

```bash
just1kbot restore
```

Скрипт позволяет выбрать локальный файл бэкапа либо применить предварительно расшифрованный SQL-дамп.

## Диагностика и устранение неполадок

### Автоматическая проверка

```bash
# На сервере бота:
just1kbot doctor

# На серверных узлах:
just1knode doctor
```

### Частые ситуации

| Ситуация | Причина | Решение |
|---|---|---|
| Бот не запускается или перезагружается | Отсутствуют обязательные переменные в `.env` или указан неверный `DB_ENCRYPTION_KEY` | Проверьте логи через `just1kbot logs bot` и конфигурацию через `just1kbot preflight` |
| Ошибка 502 Bad Gateway на `/sub/wl/` | Nginx на Origin не может связаться с ботом по SSL/SNI | Выполните `just1knode update` на Origin для сверки `proxy_ssl_name` |
| Caddy не выпускает HTTPS-сертификат | Закрыты порты 80/443 во внешнем файрволе либо не обновились DNS-записи | Запустите `just1kbot doctor` и проверьте настройки сети у хостинг-провайдера |
| Ошибка `password authentication failed` в PostgreSQL | База данных уже была создана со старым паролем в томе Docker | При чистой переустановке выполните сброс тома: `docker compose down -v` |
| Ошибка проверки SSL в `just1knode doctor` | Истек или не прошел проверку сертификат Let's Encrypt | Обновите сертификат через `certbot renew` либо переустановите через `just1knode install origin` |

## Полное удаление проекта

### Удаление бота с сервера
```bash
just1kbot uninstall
```
Утилита запросит подтверждение, остановит контейнеры, удалит volumes, очистит задания в cron и удалит рабочие каталоги.

### Удаление узла с сервера
```bash
just1knode uninstall
```
Утилита остановит службы Xray и Nginx, удалит установленные модули и очистит симлинки в `/usr/local/bin`.
