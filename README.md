# Just1kBot

Telegram-бот для продажи VPN-доступа на базе **AmneziaWG 2.0**.
Пользователь покупает подписку, создаёт устройства и получает конфигурации,
а администратор управляет серверами, тарифами, пользователями, платежами и
рассылками из Telegram.

## Возможности

### Пользователь

- пополнение внутреннего баланса через YooKassa;
- покупка, продление и смена тарифа с автоматическим перерасчетом остатка;
- создание, переименование и удаление VPN-устройств;
- моментальное получение ключа подключения (`vpn://` URI) и файлов `.vpn` / `.conf`;
- история операций, профиль подписки и реферальная программа;
- уведомления об окончании подписки и раздел поддержки.

### Администратор

- статистика пользователей, подписок, серверов и трафика;
- управление пользователями, банами, тарифами и подписками;
- пошаговое добавление и мониторинг Amnezia-серверов через Telegram;
- просмотр, ручная обработка платежей, возвратов и диспутов;
- рассылки с сохранением прогресса;
- аудит административных действий и режим технических работ.

## Архитектура и надежность

Проект спроектирован с упором на отказоустойчивость (fault-tolerance) и корректную работу в конкурентной среде:

- **Идемпотентность и атомарность:** Строгая обработка платежей, диспутов и возвратов ЮKassa, защита от race conditions с использованием row-level locks (уровня PostgreSQL).
- **Background Workers & Supervision:** Встроенный супервизор фоновых задач с heartbeat-мониторингом, circuit breaker для нод и durability-очередями на PostgreSQL с fenced-leases (проверка владельца по `locked_by` + номеру попытки).
- **Auto-healing Webhook Inbox:** Идемпотентная обработка вебхуков с автоматическим восстановлением и дедупликацией событий.
- **Безопасные вебхуки:** Корректная обработка IP-адресов от прокси-серверов (Caddy) с извлечением реальных IP-адресов клиента для защиты от SSRF и IP-спуфинга.
- **CI/CD:** Настроены процессы GitHub Actions для автоматической проверки линтером `ruff`, запуска юнит-тестов и проверки сборки Docker (smoke tests) перед деплоем.

# ⚙️ Принцип управления: Приоритет CLI-скриптов

> [!IMPORTANT]
> **Все операции производятся исключительно через скрипты `just1kbot` и `just1knode`!**
>
> - **`just1kbot`** — главная консоль на сервере бота (статус, автобэкапы, обновление с проверкой БД, логи, диагностика).
> - **`just1knode`** — главная консоль на серверах VPN-узлов (развертывание Origin/Relay, привязка каскадов, ротация ключей, обновление Xray/Nginx, автодиагностика `doctor`).
>
> Прямые команды вроде `git pull origin main`, `docker compose build`, `docker compose up -d` и ручное редактирование конфигов Nginx/Xray являются **низкоуровневыми fallback-командами для аварийной ручной отладки**. В штатном режиме всегда используйте утилиты `just1kbot` и `just1knode`, так как они обеспечивают атомарность, создание резервных копий перед обновлением, валидацию синтаксиса и zero-downtime перезагрузку.

# 🚀 Быстрый старт: Сервер бота (`just1kbot`)

Для развёртывания бота на чистом сервере (Ubuntu 22.04/24.04 или Debian 12) выполните:

```bash
git clone https://github.com/justik13/just1kbot.git
cd just1kbot
sudo bash ./scripts/setup.sh
```

Интерактивный установщик:
1. Автоматически проверит и установит Docker, Docker Compose, `age`, `openssl` и системные утилиты;
2. Пошагово запросит данные Telegram-бота, администратора, домен и ключи YooKassa с валидацией ввода на лету;
3. Автоматически сгенерирует криптографические ключи (`DB_ENCRYPTION_KEY`, пароли PostgreSQL/Redis, ключи бэкапов `age`);
4. Настроит автобэкапы в `cron`, зарегистрирует глобальную команду `just1kbot` и запустит проект в Docker.

# 🌐 Управление узлами VPN и Белого Интернета (`just1knode`)

Все серверные узлы (как входные шлюзы **Origin**, так и внешние **Relay**) настраиваются и обслуживаются через утилиту `just1knode`.

### Установка утилиты на чистый сервер узла (Ubuntu 22.04 / 24.04):

```bash
curl -fsSL https://raw.githubusercontent.com/justik13/just1kbot/main/just1knode/just1knode.sh | bash
```

Установщик развернёт модули в `/opt/just1knode` и зарегистрирует глобальную команду `just1knode`.

### Команды CLI `just1knode`:

```bash
just1knode               # Интерактивное меню управления узлом
just1knode setup-origin  # Полноценное развертывание Origin узла (Xray + Nginx + Certbot + API)
just1knode setup-relay   # Развертывание Relay узла с генерацией VLESS Reality ключей
just1knode relay add ... # Быстрое подключение Relay к Origin (в 1 клик)
just1knode update        # Обновление модулей, ядра Xray и авто-реконсиляция конфигов
just1knode doctor        # 9 уровней самодиагностики узла (Xray, API, TLS, Nginx, CDN, UFW)
just1knode status        # Проверка статуса сервисов, памяти и сетевых портов
just1knode logs          # Просмотр логов Xray, Nginx и xray-api
```

# Установка и запуск (Ручной пошаговый гайд)

> [!WARNING]
> **Только для новых установок (Greenfield)!**
> Данный способ развертывания (через Docker Compose) предназначен только для запуска бота на новых, чистых серверах. Прямая автоматическая миграция с устаревших системных (systemd/bash) установок не поддерживается. Для переноса данных необходимо вручную перенести дамп базы данных и конфигурацию.

Ниже представлен пошаговый гайд от чистого сервера до создания первого устройства. В архитектуре проекта **бот** и **VPN-серверы** разделены. Бот (Just1kBot) является панелью управления, которая общается с VPN-серверами через специальный API.

## Шаг 1. Подготовка сервера бота и домена

1. Арендуйте VPS (рекомендуется Ubuntu 22.04/24.04, минимум 1GB RAM).
2. Привяжите **доменное имя** (например, `vpn.example.com`) к IP-адресу этого сервера через A-запись в панели вашего DNS-провайдера. Это обязательно для приема вебхуков от Telegram и платежей через безопасное HTTPS соединение.
3. Подключитесь к серверу по SSH:
   ```bash
   ssh root@ip_вашего_сервера
   ```
4. Установите Docker и Docker Compose:
   ```bash
   curl -fsSL https://get.docker.com -o get-docker.sh
   sudo sh get-docker.sh
   ```

## Шаг 2. Получение токенов и ключей

1. Перейдите в Telegram к [@BotFather](https://t.me/BotFather).
2. Создайте нового бота (`/newbot`) и скопируйте его **Bot Token**.
3. (Опционально) Зарегистрируйтесь в [YooKassa](https://yookassa.ru/) и получите `Shop ID` и `Secret Key` для приема платежей.
4. Узнайте свой Telegram ID (например, через бота [@userinfobot](https://t.me/userinfobot)) — он потребуется для выдачи прав администратора.

## Шаг 3. Установка и запуск бота

1. Склонируйте репозиторий:
   ```bash
   git clone https://github.com/justik13/just1kbot.git
   cd just1kbot
   ```

2. Создайте файл настроек:
   ```bash
   cp .env.example .env
   chmod 600 .env
   ```

3. Заполните `.env` любимым редактором (например, `nano .env`):
   - Укажите ваш `BOT_TOKEN`, `ADMIN_IDS` (в формате `[123456789]`), `SUPPORT_USERNAME`.
   - Сгенерируйте `DB_ENCRYPTION_KEY` командой: `python3 -c "import secrets, base64; print(base64.urlsafe_b64encode(secrets.token_bytes(32)).decode())"`
   - Задайте надежные пароли для `POSTGRES_PASSWORD` и `REDIS_PASSWORD` (вводите обычным текстом).
   - Укажите `DOMAIN` (ваш домен) и `SSL_EMAIL` (email для получения сертификата).
   - `YOOKASSA_WEBHOOK_PORT` по умолчанию `8080` (слушается внутри сети контейнеров и проксируется через Caddy).
   - Сгенерируйте ключ для бэкапов командой `age-keygen` и вставьте публичный ключ в `BACKUP_AGE_RECIPIENT`. Приватный ключ сохраните у себя на ПК.
   - (Опционально) Укажите `BACKUP_REMOTE_URI` и `BACKUP_REMOTE_TOKEN` для автоматической выгрузки бэкапа в удалённое хранилище (S3 presigned URL).

4. Запустите проект:
   ```bash
   docker compose up -d --build
   ```

5. Проверьте статус контейнеров:
   ```bash
   docker compose ps
   ```
   Сервисы (`bot`, `db`, `redis`) должны быть `healthy`, а `caddy` — `running`. Бот готов и отвечает в Telegram!

## Шаг 4. Установка Amnezia API на VPN-ноду

Для безопасности и масштабируемости рекомендуется использовать **отдельные VPS** под VPN-ноды.

### Вариант А. Быстрая установка с Nginx + Let's Encrypt SSL (Рекомендуется)

В корне репозитория бота предусмотрен скрипт `setup-amnezia-api.sh`, который настраивает Nginx reverse proxy, выпуск сертификата Let's Encrypt, firewall (UFW) и Rate Limiting для Amnezia API на порту `8443`:

1. Подключитесь к VPS ноды по SSH.
2. Скопируйте и запустите скрипт:
   ```bash
   sudo ./setup-amnezia-api.sh --domain api.node.example.com --email owner@example.com --port 8443
   ```
3. API будет безопасно доступен по адресу `https://api.node.example.com:8443` с валидным SSL.

### Вариант Б. Ручная установка Amnezia API

1. Зайдите по SSH на сервер VPN-ноды.
2. Склонируйте репозиторий API:
   ```bash
   git clone https://github.com/kyoresuas/amnezia-api.git
   cd amnezia-api
   cp .env.example .env
   ```
3. Сгенерируйте надежный API-ключ:
   ```bash
   openssl rand -hex 32
   ```
4. Отредактируйте `.env` (`nano .env`) и вставьте полученный ключ в `FASTIFY_API_KEY`.
5. Запустите установку:
   ```bash
   bash ./scripts/setup.sh
   ```
   API запустится локально на порту `4001` (или настроенном вами).

## Шаг 5. Добавление сервера и создание 1-го устройства в боте

1. Откройте вашего бота в Telegram и отправьте команду `/admin`.
2. Перейдите в раздел **Управление серверами** ➔ **Добавить сервер**.
3. Бот пошагово запросит данные:
   - **Название сервера** (например, `Германия #1`);
   - **Эмодзи флага страны** (например, `🇩🇪`);
   - **API URL сервера** (например, `https://api.node.example.com:8443` или `http://IP:4001`);
   - **API-ключ** (ваш `FASTIFY_API_KEY`).
4. Бот проверит доступность сервера, поддержку протокола `amneziawg2`, получит лимиты и сохранит сервер в пул.
5. В админ-панели перейдите в **Управление тарифами** и настройте желаемые тарифные планы.
6. Перейдите в **Главное меню** (пользовательский интерфейс) ➔ **Мои устройства** ➔ **Создать устройство**.
7. Бот мгновенно создаст пир на сервере и предоставит:
   - **Ключ `vpn://` прямо в карточке устройства** — нажмите на моноширинный блок, чтобы скопировать URI в буфер;
   - Кнопку **«🔄 Другой способ подключения»** — для загрузки файлов `.vpn` (AmneziaVPN) и `.conf` (AmneziaWG).

Поздравляем! Ваш VPN-бот настроен и работает.

## Обновление и обслуживание

> [!IMPORTANT]
> **Приоритет автоматических утилит!**
> Не запускайте ручные команды Docker и Git без необходимости. Всегда используйте утилиты автоматизации, которые контролируют создание резервных копий и целостность базы данных.

### 1. Штатное обновление сервера бота (`just1kbot`)

На сервере бота выполните команду:

```bash
just1kbot update
```

Скрипт автоматически:
1. Создаст зашифрованный бэкап текущей базы данных PostgreSQL (`pg_dump + gzip + age`);
2. Выполнит `git pull origin main` и проверит целостность репозитория;
3. Пересоберёт Docker-образы и применит новые миграции Alembic;
4. Перезапустит сервисы и выполнит проверку их здоровья.

### 2. Штатное обновление серверов узлов (`just1knode`)

На каждом сервере узла (Origin / Relay) выполните:

```bash
just1knode update
just1knode doctor
```

Скрипт автоматически:
1. Загрузит свежие модули из репозитория GitHub и проверит их синтаксис (`bash -n`);
2. Обновит компоненты `/opt/just1knode` и демона `/opt/xray-api`;
3. Выполнит автоматическую реконсиляцию конфигов Xray и Nginx под эталонные параметры;
4. Перезагрузит Nginx (`nginx -t && systemctl reload nginx`) без разрыва активных сессий;
5. Запустит 9-уровневую диагностику здоровья узла (`doctor`).

### 3. Низкоуровневое ручное обновление (Emergency Fallback)

Используется **только** для ручной отладки или в аварийных ситуациях, если утилита `just1kbot` повреждена:

```bash
git pull origin main
docker compose build
docker compose up -d
```

### Rollback (Откат версии)

Для безопасного отката сервера бота:

```bash
# Через консоль управления:
just1kbot restore        # Восстановление БД из автоматического бэкапа

# Ручной откат кода:
git reset --hard <previous-commit>
docker compose up -d --build
```
отдельную процедуру восстановления БД из backup.

# Бэкапы и восстановление

PostgreSQL, Redis и данные Caddy хранятся в Docker volumes. Зашифрованные
PostgreSQL backups сохраняются в локальную директорию `./backups/`.

> [!CAUTION]
> **Приватный ключ `age` НИКОГДА не должен храниться на production-сервере.**
> На сервере хранится только `BACKUP_AGE_RECIPIENT` — публичный recipient для
> шифрования. Приватный ключ нужен только для расшифровки и восстановления.

> [!WARNING]
> **Ограничения Disaster Recovery**
> Локальные зашифрованные backups защищают от повреждения приложения или базы
> данных, но не являются полноценным Disaster Recovery решением. Если VPS или
> его диск будет потерян, локальные backups также будут потеряны. Для полноценного
> DR копируйте `.sql.gz.age` во внешнее независимое хранилище.

## Автоматические бэкапы через host cron

Backup container не работает постоянно. Он запускается как одноразовый job.
Для ежедневного запуска используйте cron на host-системе.

Создайте запись через `crontab -e`:

```cron
# Каждый день в 02:00
0 2 * * * flock -n /tmp/just1kbot-backup.lock sh -c 'cd /absolute/path/to/just1kbot && docker compose --profile tools run --rm backup >> /absolute/path/to/just1kbot/backups/backup.log 2>&1'
```

Замените `/absolute/path/to/just1kbot` на фактический путь проекта.
Пользователь, от имени которого работает cron, должен иметь доступ к Docker.

`flock` предотвращает параллельный запуск двух backup jobs.

## Создание бэкапа

Штатный способ через консоль управления:

```bash
just1kbot backup
```

Низкоуровневый ручной запуск без утилиты (fallback):

```bash
docker compose --profile tools run --rm backup
```

Backup выполняется по схеме:

```text
PostgreSQL
  ↓
pg_dump
  ↓
gzip
  ↓
age encrypt (BACKUP_AGE_RECIPIENT)
  ↓
*.sql.gz.age
```

После успешного шифрования plaintext dump удаляется. При ошибке backup script
также удаляет временный plaintext dump.

Старые encrypted backups старше 14 дней удаляются автоматически (политика
`rotate_backups 14` в CLI и `backup.sh`).

## Удалённые бэкапы (Offsite Remote Storage)

Для полноценного Disaster Recovery поддерживается автоматическая отправка зашифрованного архива во внешнее независимое хранилище (например, S3-совместимое хранилище через Presigned PUT URL или HTTPS-endpoint):

- В `.env` укажите:
  ```ini
  BACKUP_REMOTE_URI='https://storage.example.com/backups/{filename}'
  BACKUP_REMOTE_TOKEN='your_bearer_token'
  ```
  Плейсхолдер `{filename}` будет автоматически заменен на имя созданного файла (например, `just1kbot_20260814_120000.sql.gz.age`). Передаются исключительно зашифрованные данные.

## Восстановление

1. Скопируйте `.sql.gz.age` на локальный компьютер, где хранится private age key.
2. Расшифруйте backup локально:
   ```bash
   age -d -i private_key.txt backup.sql.gz.age > backup.sql.gz
   ```
3. Распакуйте:
   ```bash
   gunzip backup.sql.gz
   ```
4. Остановите бота:
   ```bash
   docker compose stop bot
   ```
5. Перед восстановлением создайте новый backup текущей БД.
6. Скопируйте SQL dump в PostgreSQL container:
   ```bash
   docker cp backup.sql just1kbot_db:/tmp/restore.sql
   ```
7. Восстановите dump в целевую БД. Для кастомных `POSTGRES_USER` и `POSTGRES_DB`
   значения берутся из environment самого PostgreSQL container:
   ```bash
   docker compose exec -T db sh -lc 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -f /tmp/restore.sql'
   ```

   Восстановление существующей БД может столкнуться с уже существующими таблицами
   или объектами. Для полного disaster recovery предпочтительно восстанавливать
   dump в пустую целевую БД после остановки приложения.

8. Запустите бота:
   ```bash
   docker compose start bot
   ```

9. Проверьте:
   ```bash
   docker compose ps
   docker compose logs --tail=100 bot
   ```

# Безопасность

- не коммитьте `.env`;
- не храните private age key на production-сервере (файл исключён из git и Docker-образа);
- не публикуйте `8080` бота наружу — публичный трафик должен идти через Caddy;
- используйте отдельные сильные пароли PostgreSQL и Redis;
- сужайте `TRUSTED_PROXIES` до подсети конкретного ingress (по умолчанию loopback + Docker-сеть);
- регулярно копируйте encrypted backups во внешнее хранилище.

# Troubleshooting и диагностика

## 1. Экспресс-диагностика через утилиты (Рекомендуется)

Перед ручной отладкой всегда запускайте встроенные интерактивные утилиты диагностики:

```bash
# На сервере бота (проверка БД, Redis, портов, Caddy, Telegram API):
just1kbot doctor
just1kbot logs bot

# На сервере узла VPN (проверка Xray, Nginx, Certbot, портов, proxy/ping):
just1knode doctor
just1knode logs
```

## 2. Ручная отладка контейнеров (Fallback)

### Bot перезапускается

```bash
docker compose ps -a
docker compose logs --tail=200 bot
```

Частые причины:

- отсутствует обязательная переменная в `.env`;
- неверный `DB_ENCRYPTION_KEY`;
- PostgreSQL недоступен;
- Redis недоступен;
- некорректный формат `ADMIN_IDS`;
- некорректный `DOMAIN`, `SSL_EMAIL` или YooKassa settings.

## Caddy не выдаёт HTTPS

Проверьте:

```bash
getent hosts "$DOMAIN"
ss -lntp | grep -E ':80|:443'
docker compose logs --tail=200 caddy
```

DNS для `DOMAIN` должен указывать на VPS, а порты `80/443` должны быть доступны извне.

## Ошибка `password authentication failed for user "just1kbot"`

Проблема возникает, если проект был первый раз запущен до заполнения `POSTGRES_PASSWORD` в `.env`. Docker контейнер PostgreSQL успел инициализировать базу со старым/дефолтным паролем в volume `just1kbot_postgres_data`, и изменение `.env` не меняет пароль у уже созданной базы.

**Решение для новой установки:**

Сбросьте volume базы данных и перезапустите контейнеры:

```bash
docker compose down -v
docker compose up -d
```


# Удаление проекта

Для полного удаления проекта и очистки всех созданных Docker-ресурсов (включая базы данных и хранилища):

1. **Остановите контейнеры и удалите тома данных:**
   ```bash
   docker compose down -v --rmi all
   ```
   > [!CAUTION]
   > Флаг `-v` удаляет volumes с базой данных PostgreSQL, кешем Redis и сертификатами Caddy.

2. **Удалите папку проекта:**
   ```bash
   cd ..
   rm -rf just1kbot
   ```

3. **Удалите задачу из cron (если был настроен автобэкап):**
   Выполните `crontab -e` и удалите строку с запуском бэкапов `just1kbot`.
