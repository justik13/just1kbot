# Just1kBot

Центральный серверный контроллер и Telegram-бот для управления закрытым сервисом защищенного доступа в интернет.

Архитектура комплекса разделена на два компонента:
- **`just1kbot`** (текущий репозиторий) — Telegram-бот, вебхуки, биллинг, база данных, выдача подписок и мониторинг.
- **[`just1knode`](https://github.com/justik13/just1knode)** — автономный агент серверных узлов, управляющий службами Xray, AmneziaWG и Nginx.

---

## Направления доступа и протоколы

Сервис предоставляет два независимых направления подключения:

1. **Стандартный доступ:**
   - **AmneziaWG (AWG 2.0–3.1):** реализация в ядре Linux (`awg0`) с рандомизацией заголовков и размеров пакетов (`Jc`, `Jmin`, `Jmax`, `S1-S4`, `H1-H4`, `I1-I5`). Конфигурации выдаются в форматах `vpn://` URI, `.vpn` (для AmneziaVPN и DefaultVPN) и `.conf` (для AmneziaWG).
   - **VLESS TLS:** прямое подключение на собственном домене узла. Выдача в формате HTTP Subscription Feed (`/sub/access/{token}`) для клиента INCY (iOS, Android, Windows, macOS, Linux) с квотированием устройств по HWID.
2. **Белый Интернет (для условий блокировок мобильных сетей и «белых списков»):**
   - **Xray VLESS over XHTTP:** каскадная топология Origin (РФ) -> Relay (Европа) через CDN Yandex Cloud.
   - Nginx Zero Buffering и Bodiless GET Uplink на Origin защищают от ошибок 413 и задержек CDN-буферизации.
   - Выдача строго по URL подписки (`/sub/wl/{token}`) для клиента INCY с обязательной привязкой HWID.
   - Ознакомительный доступ: 3 дня и 5 ГБ трафика (активируется один раз; продление, сброс и ручная выдача доступны в `/admin`).

## Архитектура системы

```text
                           [ Пользователи / Клиенты ]
                                       │
           ┌───────────────────────────┼───────────────────────────┐
           ▼                           ▼                           ▼
    [ Telegram Bot ]          [ AmneziaWG Client ]           [ INCY Client ]
 (Управление, биллинг,       (AmneziaVPN, DefaultVPN,     (iOS, Android, Windows,
  поддержка, рассылки)         AmneziaWG на awg0)              macOS, Linux)
           │                           │                           │
           │                           │             ┌─────────────┴─────────────┐
           ▼                           │             ▼                           ▼
 ┌───────────────────┐                 │      [ Standard VLESS ]        [ White Internet ]
 │  JUST1KBOT SERVER │                 │      (Direct VLESS TLS)       (VLESS over XHTTP)
 │ ───────────────── │                 │             │                           │
 │ • Bot (aiogram)   │                 │             │                           ▼
 │ • Caddy (HTTPS)   │                 │             │                 [ Yandex Cloud CDN ]
 │ • PostgreSQL 16   │                 │             │                           │
 │ • Redis 7.4       │                 │             │                           ▼
 │ • Task Workers    │                 │             │                 [ Origin Node (РФ) ]
 └─────────┬─────────┘                 │             │                 (Nginx Zero Buffering
           │                           │             │                  Bodiless GET Uplink)
           │ (Управляющие API          │             │                           │
           │  строго по BOT_IP)        │             │                           ▼
           ├───────────────────────────┼─────────────┼─────────────────► [ Relay Nodes ]
           ▼                           ▼             ▼                 (VLESS TLS за рубеж)
    [ Узлы AmneziaWG ]         [ Прямые VLESS ]  [ Origin / Relay ]              │
    (amnezia-api:8443)         (xray-api:8444)   (xray-api:8444)                 ▼
                                                                           [ Интернет ]
```

### Сетевое взаимодействие бота с узлами
- Узлы AmneziaWG управляются через `amnezia-api` (HTTPS, порт `8443`).
- Узлы Xray (Origin, Relay, VLESS TLS) управляются через `xray-api` (HTTPS, порт `8444`).
- Фаервол UFW на узлах открывает порты 8443 и 8444 строго для IP-адреса сервера бота (`BOT_IP`).

## Технологический стек

| Компонент | Технологии и версии | Назначение |
|---|---|---|
| Ядро бота | Python 3.12, aiogram 3.30+, aiohttp 3.14+ | Логика Telegram-интерфейса, обработка команд и меню |
| База данных | PostgreSQL 16.14-alpine, SQLAlchemy 2.0.54 (asyncpg 0.31+) | Хранение пользователей, заказов, серверов и очередей задач |

| Бэкапы | `pg_dump` + `gzip` + `age` + rclone | Зашифрованные дампы с выгрузкой в Google Drive или S3/HTTPS |

## Быстрый старт: Сервер бота

### 1. Системные требования
- ОС: Ubuntu 20.04 / 22.04 / 24.04 или Debian 11 / 12;
- Ресурсы: минимум 1 CPU, 2 GB RAM, 10 GB диска;
- Сеть: открытые внешние порты 80 и 443 (TCP);
- Доменное имя с DNS A-записью, направленной на IP сервера.

### 2. Автоматическая установка

```bash
git clone https://github.com/justik13/just1kbot.git
cd just1kbot
sudo bash ./scripts/setup.sh
```

Мастер установки `setup.sh`:
1. Устанавливает системные пакеты (`docker`, `docker compose`, `age`, `openssl`);
2. Настраивает параметры ядра: `vm.overcommit_memory=1` (в `/etc/sysctl.d/99-just1kbot.conf` для стабильной работы Redis) и Stealth ICMP (`net.ipv4.icmp_echo_ignore_all=1`);
3. Запрашивает токен бота, ID администратора, домен и API-ключи ЮKassa с проверкой формата;
4. Генерирует ключи шифрования (`DB_ENCRYPTION_KEY`, пароли PostgreSQL/Redis, ключевую пару `age`);
5. Настраивает автоматический бэкап в cron и регистрирует системную утилиту `/usr/local/bin/just1kbot`.

## Управление через CLI (`just1kbot`)

Основное управление на сервере бота выполняется через утилиту `just1kbot`.

### Интерактивное меню

```bash
just1kbot
```

### Прямые команды CLI

| Команда | Описание |
|---|---|
| `just1kbot status` | Статус контейнеров Docker, потребление памяти, дата последнего бэкапа |
| `just1kbot logs [сервис]` | Просмотр логов: `bot`, `caddy`, `db`, `redis` или `all` (по умолчанию: `bot`) |
| `just1kbot update` | Безопасное обновление: бэкап БД -> git pull -> сборка -> миграции Alembic |
| `just1kbot doctor` | Диагностика: сеть, DNS, SSL-сертификаты, Telegram API, вебхуки, аудит портов UFW |
| `just1kbot preflight` | Проверка корректности переменных окружения в `.env` |
| `just1kbot backup` | Создание зашифрованного дампа базы данных |
| `just1kbot gdrive` | Интерактивная настройка автоматической выгрузки бэкапов в Google Drive |
| `just1kbot restore [файл]` | Восстановление базы данных из локального бэкапа |
| `just1kbot config` | Редактирование `.env` с последующим пересозданием сервисов |
| `just1kbot restart [сервис]` | Перезапуск отдельного контейнера или всего проекта |
| `just1kbot start` | Запуск всех сервисов проекта |
| `just1kbot stop` | Остановка всех сервисов проекта |
| `just1kbot version` | Отображение версии проекта и текущего git-коммита |
| `just1kbot uninstall` | Полное удаление проекта (флаги: `--force`, `--purge-backups`, `--keep-backups`) |

## Резервное копирование и восстановление

### Схема шифрования дампа

```text
PostgreSQL ──> pg_dump ──> gzip ──> age (BACKUP_AGE_RECIPIENT) ──> ./backups/*.sql.gz.age
```

Публичный ключ `BACKUP_AGE_RECIPIENT` находится на сервере в `.env`. Закрытый ключ генерируется при установке, сохраняется администратором на локальном компьютере и не хранится на сервере.

### Автоматическая выгрузка в Google Drive

Для настройки выгрузки бэкапов в личное хранилище Google Drive запустите:

```bash
just1kbot gdrive
```

Команда запускает авторизацию по протоколу OAuth 2.0 и связывает изолированный контейнер `backup` с Google Drive через `rclone`. Бэкапы выгружаются в указанную папку сразу после создания по расписанию cron. Подробное руководство: [docs/GOOGLE_DRIVE_BACKUP.md](docs/GOOGLE_DRIVE_BACKUP.md).

### Выгрузка на S3 / HTTPS

Для отправки на совместимое S3/HTTPS хранилище укажите в `.env`:

```ini
BACKUP_REMOTE_URI='https://storage.example.com/backups/{filename}'
BACKUP_REMOTE_TOKEN='your_secret_token'
```

### Восстановление базы данных

```bash
just1kbot restore
```

Скрипт выводит список доступных зашифрованных дампов, принимает закрытый ключ `age` от администратора, расшифровывает дамп во временный файл и накатывает его на PostgreSQL.

## Регламент обновления в Production

Обновление распределенного сервиса выполняется строго в следующем порядке:

1. **Слияние Pull Request на GitHub:** PR мерджит владелец репозитория после успешного прохождения проверок CI.
2. **Обновление сервера бота (`just1kbot`):**
   ```bash
   just1kbot update
   ```
   Скрипт создает аварийный дамп БД, обновляет код, собирает контейнеры, накатывает миграции Alembic и проверяет статус.
3. **Обновление серверных узлов (`just1knode`):**
   На каждом узле (Origin, Relay, VLESS TLS, AmneziaWG) выполните:
   ```bash
   just1knode update
   just1knode doctor
   ```

## Биллинг, заказы и возвраты

1. **Пополнение баланса:**
   - Обработка платежей через официальный шлюз ЮKassa (СБП, банковские карты).
   - Входящие вебхуки принимаются на `/yookassa/webhook` с верификацией по официальным диапазонам IP ЮKassa и защитой от повторной обработки (идемпотентность).
2. **Атомарные списания:**
   - Баланс пользователя хранится в `users.balance_kopecks`.
   - Проверка емкости серверов и валидация ограничений тарифа выполняются до списания средств.
   - При смене тарифа выполняется перерасчет неиспользованных дней.
3. **Регламент возвратов:**
   - Возврат средств выполняется владельцем вручную через личный кабинет ЮKassa.
   - Бот принимает вебхук `refund.succeeded`, фиксирует возврат в журнале операций и отзывает доступ.

## Диагностика и частые ситуации

### Запуск диагностики

```bash
just1kbot doctor
```

Проверяет: ядро Linux, параметры `sysctl`, UFW-периметр, контейнеры Docker, коннекты к PostgreSQL и Redis, Caddy TLS/DNS, токен Telegram Bot API и доступность ЮKassa.

### Частые инциденты

| Симптом | Причина | Решение |
|---|---|---|
| Бот не стартует или циклично перезагружается | Ошибки в `.env` или неверный `DB_ENCRYPTION_KEY` | Проверьте `just1kbot logs bot` и выполните `just1kbot preflight` |
| Ошибка 502 Bad Gateway на `/sub/wl/*` | Nginx на Origin не может связаться с ботом по TLS | Выполните `just1knode update` на Origin для сверки `proxy_ssl_name` |
| Caddy не выпускает сертификат | Закрыты порты 80/443 или не обновилась DNS A-запись | Запустите `just1kbot doctor` и проверьте доступность портов во внешнем файрволе |
| Сбои TLS-пакетов при работе через туннели | MTU интерфейса хоста меньше стандартных 1500 байт | В `docker-compose.yml` мосты зафиксированы на MTU 1440. Выполните перезапуск: `just1kbot restart` |
| Ошибка доступа к API узла (8443 / 8444) | Сменился IP сервера бота либо порт закрыт в UFW узла | На сервере узла выполните `just1knode set-bot-ip <НОВЫЙ_IP>` |
