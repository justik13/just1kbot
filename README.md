# Just1kBot

Современная экосистема и Telegram-бот для продажи и автоматизированного управления VPN-доступом на базе **AmneziaWG 2.0** и **Белого Интернета (Xray VLESS over XHTTP)**.

Проект включает в себя распределённую архитектуру: центральный управляющий контроллер (**`just1kbot`**) и автономный агент узлов инфраструктуры (**`just1knode`**).

---

## ⚙️ Главный принцип управления: Strict CLI-First

> [!IMPORTANT]
> **Все штатные операции обслуживания производятся исключительно через скрипты `just1kbot` и `just1knode`!**
>
> - **`just1kbot`** — главная консоль управления на сервере бота (статус, автобэкапы, безопасное обновление с предпроверочным дампом БД, миграции, логи, doctor-диагностика).
> - **`just1knode`** — автономная утилита управления на каждом VPN-сервере (развертывание Origin и Relay, привязка каскадов, ротация ключей Reality, обновление Xray/Nginx, 9 уровней самодиагностики `doctor`).
>
> Прямые команды вроде `git pull origin main`, `docker compose build`, `docker compose up -d` и ручное редактирование конфигов Nginx/Xray являются **низкоуровневыми fallback-командами для аварийной ручной отладки**. В повседневной эксплуатации всегда используйте официальные CLI-утилиты.

## 🌟 Возможности системы

### 👤 Для пользователей
- **Два изолированных протокола:**
  - **AmneziaWG 2.0 (`amneziawg2`)**: высокоскоростной защищённый протокол с обфускацией заголовков. Выдача конфигураций в 1 клик (`vpn://` URI, `.vpn` для AmneziaVPN и `.conf` для WireGuard).
  - **Белый Интернет (`xray`)**: неуязвимый к блокировкам ТСПУ протокол VLESS over XHTTP с маскировкой под CDN Yandex Cloud и каскадной топологией Origin ➔ Relay. Бесплатный ознакомительный триал на 3 дня (10 ГБ) и инструкции для приложения **INCY** (iOS, Android, APK).
- **Финансы и биллинг:**
  - Пополнение баланса через ЮKassa (банковские карты, СБП);
  - Атомарное продление и смена тарифов с перерасчётом неиспользованного времени;
  - Реферальная программа с начислением бонусов на баланс;
  - Мгновенное обновление данных о трафике без задвоения сообщений в Telegram.

### 🛡️ Для администраторов
- **Интерактивная панель в Telegram (`/admin`):**
  - Мониторинг серверов, лимитов слотов и сетевой задержки (ping);
  - Управление тарифами, пользователями, блокировками и диспутами;
  - Рассылки пользователям с сохранением прогресса доставки;
  - Аудит административных действий и режим технических работ.
- **Интеллектуальный мониторинг узлов (`node_monitor`):**
  - Фоновый healthcheck ядра Xray и Amnezia API с CAS-защитой эпох;
  - Полностью отвязанный (decoupled) мониторинг выдачи подписок через Nginx/CDN (`/sub/wl/ping`), не роняющий ядро Xray при временных сетевых аномалиях;
  - Персистентные алерты администраторам с гарантией доставки (At-Least-Once).

## 🏗️ Архитектура и надежность

Проект спроектирован по стандартам отказоустойчивости (Fault-Tolerance) и строгой целостности данных:

1. **Strict Protocol Decoupling (Строгая изоляция контуров):**
   Контуры AmneziaWG и Xray строго изолированы. API-клиент одного протокола никогда не обращается к нодам другого протокола, а воркеры и очереди фильтруют серверы по предикату `Server.protocol`.
2. **Pre-Debit Validation & Ledger Safety:**
   Проверка тарифных ограничений и доступности серверов выполняется **до** списания средств с баланса.
3. **Lock-Before-Mutation:**
   Захват распределённых PostgreSQL Advisory Locks выполняется до отправки любых сетевых запросов к узлам.
4. **Durable-by-Default:**
   Все ключи идемпотентности, состояния очередей и инциденты мониторинга персистируются в PostgreSQL и выдерживают внезапный рестарт процесса (`kill -9`).
5. **Zero-Downtime Reloads:**
   При обновлении конфигураций узлов через `just1knode` Nginx и Xray проверяются (`nginx -t`, `xray run -test`) и перезагружаются без разрыва активных сессий клиентов.

| **Бэкапы** | `pg_dump` + `gzip` + асимметричное шифрование `age` (+ S3/HTTPS offsite) |

# 🚀 Быстрый старт: Сервер бота (`just1kbot`)

### 1. Автоматическая установка на чистый сервер (Ubuntu 22.04/24.04 или Debian 12)

```bash
git clone https://github.com/justik13/just1kbot.git
cd just1kbot
sudo bash ./scripts/setup.sh
```

Интерактивный установщик `setup.sh`:
1. Установит Docker, Docker Compose, `age`, `openssl` и системные пакеты;
2. Пошагово запросит данные бота, администратора, домен и ключи ЮKassa с валидацией на лету;
3. Сгенерирует надежные ключи шифрования (`DB_ENCRYPTION_KEY`, пароли PostgreSQL/Redis, пару ключей `age`);
4. Настроит автобэкапы в `cron`, зарегистрирует глобальную команду `just1kbot` и запустит проект в Docker.

---

### 2. Консоль управления `just1kbot`

После установки управление ботом осуществляется через единую команду:

```bash
just1kbot
```

Откроется интерактивное меню:

```text
┌─────────────────────────────────────────────────────────────┐
│                 🚀 JUST1KBOT CONTROL PANEL                  │
│                     Консоль управления                      │
└─────────────────────────────────────────────────────────────┘
  [1] 📊 Статус системы (Healthcheck контейнеров, RAM/CPU)
  [2] 📜 Просмотр логов (Live stream: Bot, Caddy, Postgres, Redis)
  [3] 🔄 Безопасное обновление (Auto-backup -> Git pull -> Rebuild)
  [4] 💾 Управление бэкапами (Создать бэкап / Восстановить БД)
  [5] ⚡ Перезапуск сервисов (Restart Bot / Restart All)
  [6] 🔑 Конфигурация (Редактировать .env файл)
  [7] 🩺 Диагностика (Doctor: DNS, SSL, порты, Telegram API)
  [8] 🧹 Очистить дисковый кэш (Docker image prune)
  [0] ❌ Выход
```

#### Прямые команды CLI:

```bash
just1kbot status         # Проверить статус здоровья контейнеров и ресурсы
just1kbot update         # Безопасное обновление: бэкап БД + pull + rebuild + миграции
just1kbot doctor         # Комплексная диагностика сети, DNS, SSL и Telegram API
just1kbot logs bot       # Просмотр логов бота в реальном времени
just1kbot backup         # Создать зашифрованный бэкап базы данных прямо сейчас
just1kbot restore        # Мастер восстановления базы данных из бэкапа
just1kbot restart        # Перезапустить бота или указанный контейнер
just1kbot clean          # Удалить неиспользуемые Docker-образы и кэш
```

# 🌐 Развертывание и управление узлами (`just1knode`)

Управление серверами VPN и Белого Интернета полностью автоматизировано через утилиту **`just1knode`**.

### 1. Установка утилиты на чистый сервер узла (Ubuntu 22.04 / 24.04):

```bash
curl -fsSL https://raw.githubusercontent.com/justik13/just1kbot/main/just1knode/just1knode.sh | bash
```

Скрипт развернет окружение в `/opt/just1knode` и сделает команду `just1knode` доступной глобально.

### 2. Развертывание входного шлюза (Origin Node в РФ)

Origin-сервер принимает трафик клиентов через Yandex Cloud CDN, осуществляет фильтрацию трафика и направляет зарубежные запросы в каскад Relay-узлов.

```bash
just1knode setup-origin
```

Установщик пошагово запросит:
- Домен узла для выпуска SSL-сертификата Let's Encrypt (например, `origin.example.com`);
- Домен бота для проксирования подписок (например, `bot.example.com`);
- CDN-домен (например, `cdn.example.com`).

После настройки Nginx будет безопасно проксировать `/sub/wl/*` на сервер бота с поддержкой TLS SNI и динамическим DNS-резолвером.

### 3. Развертывание выходного шлюза (Relay Node за рубежом)

Relay-сервер принимает замаскированный трафик с Origin через протокол VLESS Reality и обеспечивает свободный выход в глобальный интернет:

```bash
just1knode setup-relay
```

Скрипт сгенерирует ключи Reality, настроит Xray и выдаст **готовую строку подключения**.

### 4. Привязка Relay к Origin (в 1 клик)

На Origin-сервере выполните сгенерированную команду (или выберите пункт меню `[1]` в `just1knode`):

```bash
just1knode relay add "Германия" IP_RELAY PORT UUID "de" "reality" PUBKEY SHORTID SNI
```

Origin автоматически создаст индивидуальный inbound/outbound маршрут, обновит Nginx-локейшены и выполнит hot-reload без разрыва существующих соединений.

### 5. Команды CLI `just1knode`:

```bash
just1knode doctor        # 9 уровней самодиагностики узла (Xray, API, TLS, Nginx, CDN, UFW)
just1knode update        # Обновление модулей узла, Xray-core и реконсиляция конфигураций
just1knode status        # Проверка статуса служб и сетевых портов
just1knode logs          # Просмотр логов Xray, Nginx и xray-api
```

# 🚀 Протокол обновления в Production

Обновление распределенной системы выполняется строго в следующем порядке:

```
[1. GitHub Merge] ──► [2. just1kbot update] ──► [3. just1knode update]
```

### Шаг 1. Слияние PR на GitHub
Слияние Pull Request из `dev` в ветку `main` выполняется пользователем в репозитории GitHub.

### Шаг 2. Обновление сервера бота (`just1kbot`)
На сервере бота выполните штатную команду:
```bash
just1kbot update
```
Скрипт автоматически создаст резервную копию базы данных, обновит код, пересоберет образы, применит миграции Alembic и проверит здоровье сервисов.

### Шаг 3. Обновление Origin-узла (`just1knode`)
На сервере Origin выполните:
```bash
just1knode update
just1knode doctor
```
Скрипт загрузит свежие модули, проверит синтаксис, обновит Nginx-прокси подписок с корректными параметрами SNI и подтвердит прохождение всех 9 тестов здоровья.

# 🛠️ Низкоуровневый ручной Fallback (Только для отладки)

Если CLI-утилиты повреждены или недоступны, допустимо использовать прямые команды:

### Ручной перезапуск и обновление бота:
```bash
git pull origin main
docker compose build
docker compose up -d
docker compose ps
```

### Ручной запуск бэкапа базы данных:
```bash
docker compose --profile tools run --rm backup
```

### Ручной откат приложения (Rollback):
```bash
git reset --hard <previous-commit>
docker compose up -d --build
```
> [!WARNING]
> Если при обновлении применялись миграции Alembic, откат кода не откатит схему PostgreSQL автоматически. Для отката схемы используйте восстановление БД из бэкапа: `just1kbot restore`.

# 💾 Резервное копирование и Disaster Recovery

PostgreSQL, Redis и сертификаты Caddy сохраняются в постоянных томах Docker. Резервные копии БД автоматически шифруются утилитой `age` публичным ключом администратора.

### Схема шифрования:
```text
PostgreSQL ➔ pg_dump ➔ gzip ➔ age encrypt (BACKUP_AGE_RECIPIENT) ➔ ./backups/*.sql.gz.age
```

> [!CAUTION]
> **Приватный ключ `age` НИКОГДА не должен храниться на production-сервере.**
> На сервере хранится только публичный ключ `BACKUP_AGE_RECIPIENT`. Приватный ключ хранится на защищённом компьютере администратора и требуется только для расшифровки дампа при аварийном восстановлении.

### Удалённые бэкапы (Offsite S3 / HTTPS):
Для защиты от физической потери сервера укажите в `.env`:
```ini
BACKUP_REMOTE_URI='https://storage.example.com/backups/{filename}'
BACKUP_REMOTE_TOKEN='your_secret_token'
```
Архивы будут автоматически выгружаться во внешнее хранилище сразу после создания.

### Восстановление базы данных:
```bash
just1kbot restore
```
Скрипт предложит выбрать локальный бэкап или запросит расшифрованный SQL-дамп, безопасно накатив его на целевой экземпляр PostgreSQL.

# 🩺 Диагностика и устранение неполадок (Troubleshooting)

### 1. Автоматическая диагностика (Первый шаг)
Перед ручным разбором логов запустите автодиагностику:

```bash
# На сервере бота:
just1kbot doctor

# На сервере узла VPN:
just1knode doctor
```

### 2. Частые проблемы и решения

| Проблема | Причина | Решение |
|---|---|---|
| Бот не запускается / рестартится | Отсутствуют переменные в `.env` или неверный `DB_ENCRYPTION_KEY` | Запустите `just1kbot logs bot` и проверьте `.env` через `just1kbot` |
| Ошибка `502 Bad Gateway` на `/sub/wl/` | Nginx на Origin не может связаться с ботом по SSL/SNI | Выполните `just1knode update` на Origin (обновит `proxy_ssl_name`) |
| Caddy не выдает HTTPS | Порты 80/443 закрыты или DNS еще не обновился | Проверьте `just1kbot doctor` и настройки внешнего файрвола хостинга |
| Ошибка `password authentication failed` | База уже была инициализирована со старым паролем в volume | При чистой установке выполните сброс: `docker compose down -v` |
| Ошибка 60 в `just1knode doctor` | Истёк или недействителен SSL-сертификат Nginx | Выполните `certbot renew` или перевыпустите через `just1knode setup-origin` |

# 🧹 Полное удаление проекта

Для полного удаления Just1kBot с сервера с очисткой данных:

```bash
just1kbot uninstall
```

Утилита запросит подтверждение, корректно остановит контейнеры, удалит volumes, очистит cron и удалит рабочие каталоги.
