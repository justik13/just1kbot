# 🛡️ СЕТЕВАЯ БЕЗОПАСНОСТЬ, МОДЕЛЬ УГРОЗ ТСПУ И ЗАЩИТА ОТ ЗОНДИРОВАНИЯ

Настоящий документ описывает модель угроз технических средств противодействия угрозам (ТСПУ / РКН), механизмы пассивной и активной сетевой фильтрации, архитектурный принцип **Zero-Signature** («Нулевая сигнатура»), а также перечень верифицированных источников и инструментов для регулярного аудита инфраструктуры проекта **JUST1KBOT**.

---

## 1. Архитектурная модель угроз (Threat Model)

Инфраструктура проекта взаимодействует с пользователями в условиях централизованной фильтрации сетевого трафика на магистральных каналах связи (DPI / ТСПУ). Анализ сетевых потоков системами фильтрации делится на три ключевых вектора:

### 1.1. Вектор 1: Пассивная фильтрация по спискам и заголовкам (DPI L4–L7)
* **Инспекция SNI (Server Name Indication):** ТСПУ считывает поле `ServerName` в незашифрованном `ClientHello` TLS-рукопожатия. При обнаружении домена из реестра ограничений соединение немедленно разрывается (инъекция TCP RST или сброс пакетов).
* **Списки запрещённых IP-адресов (IP Blacklisting):** Блокировка конкретных IP-адресов или подсетей зарубежных хостинг-провайдеров на уровне маршрутизации BGP.
* **Блокировка сигнатур протоколов:** Системы глубокого анализа пакетов выявляют специфические паттерны заголовков, размеры рукопожатий и энтропию протоколов. Чистые протоколы без маскировки или обфускации отфильтровываются в автоматическом режиме.

### 1.2. Вектор 2: Активное зондирование (Active Probing / DPI Spiders)
* **Автоматические сетевые сканеры (Цензурные роботы, Censys, Shodan):**
  Когда с определённого зарубежного IP фиксируется необычный сетевой трафик, автоматические сканеры ТСПУ инициируют обратное сканирование этого IP:
  1. Выполняется подключение к открытым портам (`80`, `443`, `8080`, `8443` и др.) напрямую по IP-адресу без указания SNI.
  2. Запрашивается корневой путь (`GET / HTTP/1.1`) или типовые пути веб-серверов.
  3. Если веб-сервер отдаёт **HTTP-редирект** (`301` / `308`) с указанием реального доменного имени (например, `Location: https://bot.example.pro/`), сканер мгновенно деанонимизирует связку `IP <-> Домен`.
  4. Если веб-сервер отдаёт TLS-сертификат, содержащий доменное имя в полях Common Name или Subject Alternative Name (SAN), связка `IP <-> Домен` фиксируется автоматически.
  5. После деанонимизации IP заносится в списки блокировки ТСПУ.

### 1.3. Вектор 3: Эвристический поведенческий анализ (Behavioral / Volume Analysis)
* Сопоставление объёма входящего и исходящего трафика, длительности сессий и среднего размера пакетов.
* **«Парадокс маскировки» (Camouflage Paradox):** Попытка замаскировать высоконагруженный узел под статическую HTML-страничку (5–10 КБ текста, простейший калькулятор) привлекает повышенное внимание эвристик. В реальности веб-сайт с 5 КБ текста не может генерировать сотни гигабайт непрерывного потокового трафика.

## 2. Архитектура Zero-Signature (Реализация в проекте)

В проекте принята концепция **Zero-Signature** — отказ от фальшивых сайтов-ловушек в пользу строгого закрытия соединений и изоляции сетевого периметра.

```
       [ Входящий запрос ]
               │
        ┌──────┴──────┐
        ▼             ▼
   [ Порт 80 ]   [ Порт 443 ]
        │             │
  Host == DOMAIN?   SNI == DOMAIN?
     ┌──┴──┐           ┌──┴──┐
    ДА    НЕТ         ДА    НЕТ
     │     │           │     │
  Redir  abort      Штатная  Сброс TLS /
  HTTPS  (Drop)     работа   HTTP 421
```

### 2.1. Caddy: Изоляция точки входа Telegram-бота
1. **Директива `strict_sni_host`:**  
   В глобальном блоке `servers` Caddy активирован параметр `strict_sni_host`. Он гарантирует, что заголовок HTTP `Host` обязан строго совпадать со значением `ServerName`, переданным в TLS ClientHello. Запросы с несовпадающим хостом получают `HTTP 421 Misdirected Request`, предотвращая атаки типа domain fronting.
2. **Сброс прямых IP-проб (`abort` на HTTP/80):**  
   Блок `http://` на порту 80 проверяет хост:
   - Если `Host == {$DOMAIN}`: выполняется штатное перенаправление на HTTPS.
   - Любые другие запросы (прямой опрос по IP, обращение сканеров, случайные сканы) мгновенно сбрасываются директивой `abort` без отправки каких-либо заголовков или раскрытия домена.
3. **Отсутствие сертификата по умолчанию на HTTPS/443:**  
   При прямом подключении по IP на порт 443 TLS-рукопожатие аварийно прерывается, поскольку у Caddy нет дефолтного сертификата для IP-адресов. Сканер не может прочитать домен из SAN.
4. **Стандартные коды ошибок:**  
   Все немаршрутизируемые запросы получают стандартный `404 Not Found` без уникальных HTML-сигнатур, баннеров или служебных заголовков (`-Server`).

### 2.2. Защита Origin и Relay узлов
1. **Origin (Порт 8444):**  
   Порт Management API узла защищён фаерволом UFW по принципу **Strict Whitelist**: доступ разрешён строго с одного IP-адреса Telegram-бота (`BOT_IP`). Любые внешние зонды на порт 8444 отбрасываются фаерволом (DROP / TIMEOUT).
2. **Relay (Порт 10443):**  
   Порт туннеля между Relay и Origin изолирован фаерволом UFW строго для IP-адреса Origin (`ORIGIN_IP`). Доступ из остального интернета полностью закрыт.
3. **Белый Интернет (Yandex Cloud CDN):**  
   Используется протокол XHTTP (SplitHTTP) over CDN с маскировкой под разрешённый CDN-трафик отечественной инфраструктуры. Подробное описание приведено в [`docs/WL/WHITELIST_MASTER_GUIDE.md`](WL/WHITELIST_MASTER_GUIDE.md).

## 3. Реестр проверенных источников и ресурсов

Для актуализации данных о сетевой фильтрации, новых алгоритмах ТСПУ и методах защиты используются следующие профильные ресурсы:

### 3.1. Исследовательские форумы и сообщества
* **[NTC Party](https://ntc.party/):**  
  Ключевой русскоязычный технический форум по исследованию методов анализа трафика ТСПУ, сигнатур DPI, проблем резолвинга DNS и поведенческих блокировок.  
  *Примечание:* Доступ к ресурсу может требовать IPv6 или туннелирование, так как форум находится под фильтрацией ТСПУ.
* **[Net4People BBS](https://github.com/net4people/bbs):**  
  Международный форум исследователей цензуры и обхода сетевых ограничений. Содержит подробные отчёты об активном зондировании (Active Probing), классификации трафика нейросетями и сигнатурном анализе.

### 3.2. Анализ DPI и поведенческие инструменты
* **[bol-van / zapret](https://github.com/bol-van/zapret) & [zapret2](https://github.com/bol-van/zapret2):**  
  Эталонный открытый инструментарий для исследования работы ТСПУ и обхода сигнатурных фильтров DPI на уровне пакетов (фрагментация TCP/TLS, подделка заголовков, обход эвристик).
* **[kort0881 / russia-whitelist](https://github.com/kort0881/russia-whitelist):**  
  База данных разрешённых IP-адресов и сетей РФ для оптимальной маршрутизации и предотвращения ложных срабатываний.
* **[CraftStick / node-installer-cdn](https://github.com/CraftStick/node-installer-cdn):**  
  Исследования и скрипты интеграции туннелей через российские сети доставки контента (CDN).

### 3.3. Официальная документация компонентов
* **[Caddy Server Documentation](https://caddyserver.com/docs/):**  
  Официальная документация веб-сервера Caddy (`strict_sni_host`, `abort`, `auto_https`, директивы заголовков).
* **[XTLS / Xray-core](https://github.com/XTLS/Xray-core):**  
  Спецификации и реализация современных протоколов передачи данных (XHTTP, VLESS Vision).

## 4. Чеклист проверки узла перед запуском (Zero-Probing Checklist)

1. [ ] **Порт 80 (HTTP):** Прямой опрос `curl -v http://<IP>/` завершается сбросом соединения (`Empty reply / connection closed`). Редирект отдаётся только при наличии заголовка `Host: <DOMAIN>`.
2. [ ] **Порт 443 (HTTPS):** Прямой опрос `curl -k -v https://<IP>/` завершается ошибкой рукопожатия TLS, доменный сертификат сканеру не передаётся.
3. [ ] **Порт 8444 (Origin API):** Закрыт в UFW для всех адресов, кроме актуального `BOT_IP`.
4. [ ] **Порт 10443 (Relay Tunnel):** Закрыт в UFW для всех адресов, кроме актуального `ORIGIN_IP`.
5. [ ] **DNS-резолверы на Origin:** Используют отечественные DNS (Яндекс 77.88.8.8, MSK-IX 195.208.4.1), исключая задержки от фильтрации UDP:53 к зарубежным DNS.
