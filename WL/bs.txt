# ИНСТРУКЦИЯ: Настройка VLESS XHTTP + Padding через Yandex Cloud CDN

**Актуальность:** Июль 2026 г.
**Архитектура:** Клиент ➡️ Yandex Cloud CDN ➡️ Origin-сервер (Aeza МСК: Nginx + Xray) ➡️ Exit-сервер (Германия: Xray) ➡️ Свободный интернет

---

## 0. ИСХОДНЫЕ ДАННЫЕ И ПЕРЕМЕННЫЕ

* **Основной домен:** `example.com`

* **Origin-домен (Aeza МСК):** `origin.example.com` (IP: `185.146.131.64`)


* **Exit/Relay-домен (Германия):** `relay.example.com` (IP: `94.249.239.200`)


* **CDN-домен:** `cdn.example.com`

* **Единый UUID:** `a2b9d4e1-73c5-4812-b964-f3e7b85a1902`
* **Секретный путь XHTTP:** `/api/v3/secure-data`
* **Ключ Padding:** `dc`

* **Email для Let's Encrypt:** `admin@example.com`


---

## 1. НАСТРОЙКА DNS (CLOUDFLARE)

В панели Cloudflare для домена `example.com` должны быть созданы следующие записи с выключенным проксированием (серые облака — **«DNS Only»**):

1. **A-запись `origin**` ➡️ указывает на `185.146.131.64`

2. **A-запись `relay**` ➡️ указывает на `94.249.239.200`

3. **CNAME-запись `_acme-challenge.cdn**` ➡️ проверочный адрес из Certificate Manager


4. **CNAME-запись `cdn**` ➡️ указывает на служебный адрес CDN Яндекса (выдается после создания CDN-ресурса)

## 2. EXIT-СЕРВЕР: ГЕРМАНИЯ (XRAY + TLS)

Подключись к серверу в Германии под `root`. Убедись, что порты 80 и 10443 открыты.

### 2.1. Инициализация переменных

```bash
export RELAY_HOST='relay.example.com'
export UUID='a2b9d4e1-73c5-4812-b964-f3e7b85a1902'
export EMAIL='admin@example.com'

```

### 2.2. Установка ПО и выпуск сертификата



```bash
apt update && apt install -y curl certbot
bash -c "$(curl -L https://github.com/XTLS/Xray-install/raw/main/install-release.sh)" @ install --version 26.5.9

# Выпуск сертификата через Standalone-режим (порт 80 должен быть свободен)
certbot certonly --standalone --non-interactive --agree-tos --email "$EMAIL" -d "$RELAY_HOST"

# Копирование сертификатов с правами для группы nogroup
install -d -m 750 -o root -g nogroup /usr/local/etc/xray/tls
install -m 640 -o root -g nogroup "/etc/letsencrypt/live/${RELAY_HOST}/fullchain.pem" /usr/local/etc/xray/tls/fullchain.pem
install -m 640 -o root -g nogroup "/etc/letsencrypt/live/${RELAY_HOST}/privkey.pem" /usr/local/etc/xray/tls/privkey.pem

```

### 2.3. Создание конфигурации Xray



```bash
cat > /usr/local/etc/xray/config.json <<EOF
{
  "log": {
    "loglevel": "warning"
  },
  "inbounds": [
    {
      "tag": "from-origin",
      "listen": "0.0.0.0",
      "port": 10443,
      "protocol": "vless",
      "settings": {
        "users": [
          {
            "id": "${UUID}",
            "flow": "xtls-rprx-vision"
          }
        ],
        "decryption": "none"
      },
      "streamSettings": {
        "network": "tcp",
        "security": "tls",
        "tlsSettings": {
          "alpn": ["h2", "http/1.1"],
          "certificates": [
            {
              "certificateFile": "/usr/local/etc/xray/tls/fullchain.pem",
              "keyFile": "/usr/local/etc/xray/tls/privkey.pem"
            }
          ]
        }
      }
    }
  ],
  "outbounds": [
    {
      "tag": "internet",
      "protocol": "freedom"
    }
  ]
}
EOF

```

### 2.4. Запуск службы и хук автопродления



```bash
# Проверка и запуск
/usr/local/bin/xray run -test -config /usr/local/etc/xray/config.json
systemctl enable xray
systemctl restart xray

# Создание хука автообновления сертификатов в Xray
install -d /etc/letsencrypt/renewal-hooks/deploy
cat > /etc/letsencrypt/renewal-hooks/deploy/restart-xray.sh <<'EOF'
#!/bin/sh
set -eu
install -m 640 -o root -g nogroup "${RENEWED_LINEAGE}/fullchain.pem" /usr/local/etc/xray/tls/fullchain.pem
install -m 640 -o root -g nogroup "${RENEWED_LINEAGE}/privkey.pem" /usr/local/etc/xray/tls/privkey.pem
systemctl restart xray
EOF
chmod 755 /etc/letsencrypt/renewal-hooks/deploy/restart-xray.sh

```

### 2.5. Настройка Firewall (UFW)



Рекомендуется разрешить порт `10443` только с IP-адреса Origin-сервера (Аэзы):

```bash
ufw allow from 185.146.131.64 to any port 10443 proto tcp

```

## 3. ORIGIN-СЕРВЕР: AEZA МСК (NGINX + XRAY)

Подключись к серверу в Москве под `root`.

### 3.1. Исправление работы системного DNS (для РФ)



В некоторых случаях у провайдера могут быть проблемы с DNS. Пропишем стабильные DNS-серверы Яндекса и Google:

```bash
cat > /etc/resolv.conf <<EOF
nameserver 77.88.8.8
nameserver 8.8.8.8
nameserver 1.1.1.1
EOF

```

### 3.2. Установка ПО и обход блокировок GitHub (Локальная установка Xray)



Так как прямые запросы к GitHub в РФ блокируются, используем рабочее зеркало для скачивания дистрибутива:

```bash
apt update && apt install -y nginx certbot curl wget unzip

# Скачивание скрипта и архива Xray-core через зеркало
wget -O install-release.sh https://gh.ddlc.top/https://raw.githubusercontent.com/XTLS/Xray-install/main/install-release.sh
chmod +x install-release.sh
wget -O Xray-linux-64.zip https://gh.ddlc.top/https://github.com/XTLS/Xray-core/releases/download/v26.5.9/Xray-linux-64.zip

# Запуск локальной установки и очистка временных файлов
./install-release.sh install --local Xray-linux-64.zip
rm -f install-release.sh Xray-linux-64.zip

```

### 3.3. Чистка конфликтующих конфигураций Nginx



Для предотвращения ошибок `conflicting server name` удали дефолтные конфиги и отключи конфликтующие (например, старые WebSocket-конфигурации):

```bash
rm -f /etc/nginx/sites-enabled/default
# Если в conf.d есть файлы, использующие те же домены, переименуй их
mv /etc/nginx/conf.d/vless-websocket.conf /etc/nginx/conf.d/vless-websocket.conf.bak 2>/dev/null

```

### 3.4. Получение SSL-сертификата Let's Encrypt для Origin



```bash
install -d -m 755 /var/www/acme

# Создаем временный конфиг для прохождения ACME-челленджа
cat > /etc/nginx/sites-available/xhttp-origin.conf <<'EOF'
server {
    listen 80;
    listen [::]:80;
    server_name origin.example.com;

    location ^~ /.well-known/acme-challenge/ {
        root /var/www/acme;
    }

    location / {
        default_type text/plain;
        return 200 "origin is ready\n";
    }
}
EOF

ln -sfn /etc/nginx/sites-available/xhttp-origin.conf /etc/nginx/sites-enabled/xhttp-origin.conf
nginx -t && systemctl enable --now nginx && systemctl reload nginx

# Выпускаем сертификат
certbot certonly --webroot -w /var/www/acme --non-interactive --agree-tos --email "admin@example.com" -d "origin.example.com"

```

### 3.5. Создание конфигурации Xray на Аэзе



Конфиг перенаправляет трафик с локального XHTTP-порта `8003` на внешний порт Германии `10443`.

```bash
cat > /usr/local/etc/xray/config.json <<'EOF'
{
  "log": {
    "loglevel": "warning"
  },
  "inbounds": [
    {
      "tag": "from-yandex-cdn",
      "listen": "127.0.0.1",
      "port": 8003,
      "protocol": "vless",
      "settings": {
        "users": [
          {
            "id": "a2b9d4e1-73c5-4812-b964-f3e7b85a1902"
          }
        ],
        "decryption": "none"
      },
      "streamSettings": {
        "network": "xhttp",
        "security": "none",
        "xhttpSettings": {
          "mode": "packet-up",
          "path": "/api/v3/secure-data",
          "xPaddingObfsMode": true,
          "xPaddingKey": "dc",
          "xPaddingHeader": "X-Cache",
          "xPaddingMethod": "tokenish",
          "xPaddingPlacement": "queryInHeader"
        }
      }
    }
  ],
  "outbounds": [
    {
      "tag": "to-exit",
      "protocol": "vless",
      "settings": {
        "vnext": [
          {
            "address": "94.249.239.200",
            "port": 10443,
            "users": [
              {
                "id": "a2b9d4e1-73c5-4812-b964-f3e7b85a1902",
                "encryption": "none",
                "flow": "xtls-rprx-vision"
              }
            ]
          }
        ]
      },
      "streamSettings": {
        "network": "tcp",
        "security": "tls",
        "tlsSettings": {
          "serverName": "relay.example.com",
          "alpn": ["h2", "http/1.1"]
        }
      }
    },
    {
      "tag": "direct",
      "protocol": "freedom"
    },
    {
      "tag": "block",
      "protocol": "blackhole"
    }
  ]
}
EOF

# Проверка и запуск
/usr/local/bin/xray run -test -config /usr/local/etc/xray/config.json
systemctl enable xray
systemctl restart xray

```

### 3.6. Настройка постоянного боевого Nginx



Удалены устаревшие директивы `http2_max_field_size` и `http2_max_header_size` во избежание предупреждений.

```bash
# Добавляем маппинг OPTIONS -> POST
cat > /etc/nginx/conf.d/xhttp-method.conf <<'EOF'
map $request_method $xhttp_proxy_method {
    default  $request_method;
    OPTIONS  POST;
}
EOF

# Создаем боевой конфиг
cat > /etc/nginx/sites-available/xhttp-origin.conf <<'EOF'
server {
    listen 80;
    listen [::]:80;
    server_name origin.example.com;

    location ^~ /.well-known/acme-challenge/ {
        root /var/www/acme;
    }

    location / {
        return 301 https://$host$request_uri;
    }
}

server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name origin.example.com;

    ssl_certificate     /etc/letsencrypt/live/origin.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/origin.example.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;

    client_max_body_size 0;
    client_header_buffer_size 64k;
    large_client_header_buffers 8 128k;

    # Точка для проверки CDN-соединения
    location = /cdn-check {
        add_header X-CDN-Origin "ok" always;
        add_header X-Origin-Method $request_method always;
        add_header X-Origin-Content-Length $http_content_length always;
        return 204;
    }

    location /api/v3/secure-data {
        proxy_pass http://127.0.0.1:8003;
        proxy_method $xhttp_proxy_method;
        proxy_http_version 1.1;
        proxy_set_header Connection "";

        proxy_pass_request_headers on;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_buffering off;
        proxy_request_buffering off;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }
}
EOF

# Проверяем синтаксис и перезапускаем Nginx
nginx -t && systemctl restart nginx

# Настройка автоперезапуска Nginx после обновления сертификатов
install -d /etc/letsencrypt/renewal-hooks/deploy
cat > /etc/letsencrypt/renewal-hooks/deploy/reload-nginx.sh <<'EOF'
#!/bin/sh
systemctl reload nginx
EOF
chmod 755 /etc/letsencrypt/renewal-hooks/deploy/reload-nginx.sh

```

## 4. НАСТРОЙКА YANDEX CLOUD CDN

Настройка в консоли Yandex Cloud выполняется по следующим жестким правилам:

### 4.1. Добавление сертификата в Certificate Manager



1. Создай сертификат от Let's Encrypt для домена: `cdn.example.com`.


2. Выбери DNS-тип проверки и добавь полученную CNAME-запись в Cloudflare.


3. Дождись статуса **«Issued» / «Выпущен»**.



### 4.2. Настройка Группы источников



1. Перейди в **Cloud CDN** ➡️ **Группы источников** ➡️ Создать группу.


2. Название: `common-just1kbest`.


3. Тип источника: **Сервер**.


4. Доменное имя источника: строго **`origin.example.com`** (Не IP! Использование IP приведет к ошибкам SSL Handshake и HTTP 502).



### 4.3. Настройка CDN-ресурса



При создании CDN-ресурса укажи:

* **Основное доменное имя:** `cdn.example.com`

* **Группа источников:** `common-just1kbest`

* **Протокол для источников:** строго **HTTPS** (порт 443)


* **Заголовок Host:** Выбрать «Свое значение» ➡️ строго **`origin.example.com`**

* **Имя SNI-хоста:** строго **`origin.example.com`**

* **Тип сертификата:** Использовать из Certificate Manager (выбери ранее выпущенный)


* **Перенаправление клиентов:** С HTTP на HTTPS


* **Кеширование:** Отключить полностью (и в браузере, и на CDN). «Игнорировать параметры запроса» — выключено.


* **Разрешенные методы:** GET, HEAD, OPTIONS (OPTIONS должен быть явно разрешен!)

## 5. ПРОВЕРКА СОЕДИНЕНИЯ (ЧЕРЕЗ ГЕРМАНИЮ ИЛИ ЛЮБОЙ ПК)

Выполни на сервере в Германии (или на домашнем ПК) команду отправки запроса OPTIONS:

```bash
curl -sS -D - -o /dev/null -X OPTIONS "https://cdn.example.com/cdn-check?nocache=$(date +%s)"

```

**Ожидаемый ответ:**

```http
HTTP/2 204
server: nginx
x-cdn-origin: ok
x-origin-method: OPTIONS

```

Если в логах Nginx на Аэзе (`tail -f /var/log/nginx/access.log`) мгновенно отображается этот запрос — вся система работает безукоризненно!

## 6. НАСТРОЙКА КЛИЕНТА (V2RAYNG / HAPP / NEKOBOX)

Создай VLESS-профиль со следующими параметрами:

* **Address:** `cdn.example.com`

* **Port:** `443`

* **UUID:** `a2b9d4e1-73c5-4812-b964-f3e7b85a1902`
* **Encryption:** `none`

* **Network:** `xhttp`

* **Mode:** `packet-up`
* **Path:** `/api/v3/secure-data`
* **TLS:** `tls` (Включено)


* **SNI:** `cdn.example.com`

* **Host:** `cdn.example.com`

* **Fingerprint (Utop):** `firefox` (или `chrome`)
* **ALPN:** `h2`
